## How a candidate was compared

Each candidate's exact bytes (the host store
`${XDG_CACHE_HOME:-$HOME/.cache}/crozier/witness-populations/<sha256>`) were
generated by Fern in both enum modes, one generation at a time under the shared
`fern-generation.lock`, and published to the certified-tree store with
`tools/fern-goldens/certified_tree.py publish`; no published tree carries an
`originGitCommit`. crozier's tree for the same bytes was compared whole with
`crozier compare` (reference command: copy the certified tree), so every file
is either byte-equal after comment stripping or listed. Every candidate was
compared again with the finished generator (this change's repairs included), so
each outcome below is that of the finished tree. [`certified.tsv`](certified.tsv)
holds one row per candidate and mode: its outcome is `byte-match`,
`repaired-here` (a difference this change repairs in crozier), a catalogued
departure, an `attributed-residual` (a difference outside the key's interaction,
named in `detail`), or a Fern refusal.

## Differences repaired here

The certified screen found these generator differences inside the keys' own
conjunctions, each now matching the certified pair on the real document and held
to a from-scratch measurement under
[`../../fern-measurements/union-inheritance/`](../../fern-measurements/union-inheritance/)
(`nullable-unknown-success-body`, `map-beside-union`,
`unrequired-const-tag-union`, `allof-unrequired-tag-branches`,
`annotated-ref-description-precedence`) by
`crates/crozier-e2e/tests/e2e/union_inheritance.rs`, in both enum modes:

- `combo-success-anyof-nullable`: a success body `anyOf: [{}, null]` returns
  `Optional[Any]` (`9867c34e…`), and a response map whose value is a scalar
  beside `null` is `Dict[str, Optional[str]]` with no value union (`672f1ef2…`,
  `88e57c60…`).
- `combo-map-beside-oneof`: `additionalProperties` beside a `oneOf`/`anyOf` is
  the map on every path — a discriminated component is `Dict[str, Any]` whose
  members keep their tag (`66375934…`, `bd47e5be…`), a `$ref` body to it is
  sent unconverted, and an inline body is the map body with its content-type
  header (`672f1ef2…`).
- `combo-unrequired-tag-oneof-reference`: a bare `const` `type` tag a member
  leaves unrequired does not discriminate (`c3445e5e…`, `83f6c0ba…`), and an
  `allOf` member's undiscriminated `oneOf` of `$ref`s with an unrequired tag
  lends its branches' properties, the first spelling winning, its branches
  keeping the tag (`cb07c78d…`); a written discriminator still strips it
  (`062aa5f0…`).
- `combo-annotated-ref-to-nullable-target`: a required field written
  `allOf: [$ref, {description}]` beside a description of its own is
  documented by the annotating member's sentence and an optional one by its
  own, and every use-site copy (enum, object, component alias) takes the
  member's (`annotated-ref-description-precedence`; exposed by the key's
  independence documents, not by a screen candidate).
- #826 and #827, where their root causes recurred on screened documents
  (manager ruling a13: a ticket fixed only for its named specification is not
  fixed), each held to `inlined-chain-inheritance`: an inlined parent's
  property hoists its inline type under the component declaring it (epilot's
  `AutomationActionConfigReason`, `b39e4f49…`); an inlined chain writes each
  level's own fields before its parents' (Mistral's `FIMCompletionResponse`,
  `94f7d515…`); a restatement writing no `nullable` keeps the parent's
  (hyperdx's `AlertResponse`, `8d4010ac…`); overlapping parents are inlined
  while an untouched one stays a base (the TypePlate documents above); and a
  nullable free-form object component keeps its nullability (uploadcare's
  `metadata`, `2af57889…`).
