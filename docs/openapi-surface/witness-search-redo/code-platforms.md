## Returned failures

- **Sourcegraph:** the control `curl -sS -G https://sourcegraph.com/.api/search/stream --data-urlencode v=V3 --data-urlencode 'q=file:openapi.yaml content:"scheme: bearer" count:20 type:file'` returned HTTP 200 but a completed stream with `matchCount: 0` and explicit skipped families (66,224 archived repositories and 281 forks). The owned queries use the same body index, but its default exclusions make their result sets incomplete; this is an inaccessible index family, not zero.
- **GitHub code search:** the required preflight `gh api rate_limit --jq '.resources.search'` returned limit 30, remaining 30. The control `gh api -X GET search/code -f q='"scheme" "bearer" filename:openapi.yaml' -f per_page=1` returned `total_count: 28928` and a real blob, proving body search works. The owned sweep then hit the secondary limiter while the primary endpoint still reported 30 of 30 remaining: the first refusal was HTTP 403, request `9D4A:ED00:24CD72:78CED4:6AA180BE`, at 2026-09-09 15:52:30 UTC. Six already-issued loop iterations returned the same refusal family before the sweep stopped; no call was retried after inspection. The two calls answered before the refusal each returned zero literal matches, but literal search cannot express the structural selectors, so they are not declaration zeros. All GitHub records are therefore `unanswered`.
- **SwaggerHub:** the control `curl -sS -G https://api.swaggerhub.com/specs --data-urlencode query=petstore --data-urlencode limit=1` returned HTTP 200 and `totalCount: 129609`. Responses contain registry metadata and mutable `owner/api/version` download links, not body-search results or immutable references. The owned queries therefore cannot answer declarations.
- **Postman:** the control `curl -sS https://www.postman.com/_api/ws/proxy -H 'content-type: application/json' --data '{"service":"search","method":"POST","path":"/search-all","body":{"queryIndices":["adp.api"],"queryText":"petstore","size":1,"from":0}}'` returned HTTP 200 and an API metadata hit. Every owned query returned `invalidParamsError` with `Size value: 100 must be non-negative integer and less than 26.` Even a successful response exposes metadata rather than public definition bodies; without bodies, the selector evaluator cannot qualify declarations.

Because no plausible hit could be retained from an exhaustive, body-readable result
set, there is no publisher, immutable-reference, licence, or Fern screen to record.
The authoritative rows in `../schemas.md` remain unchanged.
