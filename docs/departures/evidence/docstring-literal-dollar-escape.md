# A docstring example escaping a const's `$`

The independently authored
[`prompt-variable`](../../openapi-surface/handwritten/prompt-variable/openapi.yml)
source posts a `PromptSpec` body requiring `variable`, declared
`type: string, const: $PS1`, beside a plain string `label` exampled
`Costs $5 at $HOST`. Its complete unedited certified tree was generated by Fern
CLI 5.67.1 and `fernapi/fern-python-sdk` 5.20.0 (packaged preview layout,
organization and package `fern`, project `default_package_name`, no audience
filter, `pydantic_config.enum_type: python_enums`); the overlay under
[`docs/fern-measurements/literals-mode/prompt-variable`](../../fern-measurements/literals-mode/prompt-variable/)
records the same source with `enum_type` unset, the mode the fault appears in.

Under literals the const lowers to `PromptSpecVariable =
typing.Union[typing.Literal["$PS1"], typing.Any]`. Fern's README and
`reference.md` pass `variable="$PS1"`, but both client docstrings pass
`variable="\\$PS1"`. Python evaluates that docstring source to `\$PS1` — the
const with a backslash prepended — so the documented example passes a value the
const does not admit and contradicts Fern's own Markdown examples. The
`label` example keeps its bare `$` in every writer, and under `python_enums`
the const is the member `PromptSpecVariable.PS1`; neither is affected. crozier
writes `variable="$PS1"` in the docstrings, as Fern's Markdown does.

## Executed certified-output evidence

Materialize the certified literals tree — the handwritten `fern-expected/`
minus the overlay manifest's `removed` files, with the overlay's files laid
over it, as `literals_mode_measurements_match_fern` rebuilds it — then run the
committed [validator](docstring-literal-dollar-escape.py). It imports the
generated package, evaluates the `variable` argument of the sync and async
client docstring examples and of every README/`reference.md` worked call
exactly as Python evaluates their source, binds each docstring call to the
actual generated method, and compares each value with the declared const and
the generated `Literal`. Executed on 2026-10-10 with Python 3.14 and PyYAML
6.0.3 from the repository environment:

```sh
PYTHONDONTWRITEBYTECODE=1 python docs/departures/evidence/docstring-literal-dollar-escape.py \
  <materialized literals tree> \
  docs/openapi-surface/handwritten/prompt-variable/openapi.yml \
  --schema PromptSpec --literal-type PromptSpecVariable \
  --method define_prompt --keyword variable --examples invalid
```

It exited 0, reporting:

```text
{"const": "$PS1", "docstrings": {"AsyncFernApi.define_prompt": "\\$PS1", "FernApi.define_prompt": "\\$PS1"}, "examples": "invalid", "literal": ["$PS1"], "markdown": {"README.md#0": "$PS1", "README.md#1": "$PS1", "reference.md#0": "$PS1"}}
```

With `--examples valid` it exits 1 on the certified tree. Over the tree the
compiled crozier binary generated from the same source with
`--enum-type literals` it exits 0 with `--examples valid`, every docstring and
Markdown value equal to `$PS1`.

## The parity rule

The rule accepts one aligned line pair of a high-level `client.py` docstring's
`Examples`, a keyword passed a double-quoted string literal equal to a string
`const` the parsed source document declares, where Fern's line is crozier's
with every `$` preceded by an escaped backslash. It never applies without the
source document, to a string no `const` declares (the `label` control), to
`README.md`, `reference.md`, a raw client, a line outside an example, or to any
other difference. The line ledger is recorded from `src/parity.rs`, never
hand-edited.
