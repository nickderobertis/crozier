# OpenAPI surface coverage — Schemas

Classified entries for the `schemas` region, against the boundary in
`## Scope` below.

This inventory is derived mechanically from the two normative schema surfaces,
not from crozier's data model: the fixed-field list under the OpenAPI 3.0 Schema
Object, then each JSON Schema 2020-12 vocabulary named by OpenAPI 3.1 (Core,
Applicator, Unevaluated, Validation, Meta-data, Format-Annotation,
Format-Assertion, and Content), then the four OpenAPI 3.1 Schema Object additions.
The final rows add the structural schema forms required by those specifications
and the fixed fields of the Discriminator and XML Objects. To repeat the walk,
copy those lists in specification order, de-duplicate identical keywords, retain
semantic variants as called out below, and query each as `schema.<field>` (or
`schema.format=<value>`) with `just surface-census --json`.

The census walks nested schemas, so a keyword count includes every legal schema
position. It does not, however, record boolean-schema values, graph topology,
the presence of siblings beside `$ref`, scalar versus array `type`, the value
kind of `exclusive*`, or a composition keyword's parent context. Those
structural variants therefore use exact limitations evidence where available
and otherwise remain gaps. `nullable`, `example`, and
`examples` remain separate rows because they are distinct keywords with
different version ranges. `format` has its keyword row plus one row per 2020-12
registry value; annotation collects a value, while assertion makes it a
validation requirement.

Fields in other OpenAPI objects that merely *hold* a Schema Object belong to
their owning regions; this file classifies the Schema Object and all JSON Schema
keywords wherever the census reaches them.

## Scope

Schema, Discriminator and XML objects, and every JSON Schema keyword wherever it
appears, including the ones 3.1 added.

## Method notes

This table is a dated audit snapshot, measured on 2026-08-23, rather than a
second authority for the corpus or limitations ledger. `just surface-census
--json` supplied every fixture name and declaration count; an absent selector
meant zero across every source registered at measurement time. The limitations

re-measure and replace the table as one snapshot rather than updating individual
cells. No Fern generation or probe was run for this classification.
