# union-modelling: singleton-enum-tags

A sub-case of the [`union-modelling`](../README.md) cause; **verdict: parity-gap-repaired**.

`openapi.yml` was authored from scratch for this rule. `fern-expected/` is Fern CLI 5.163.1 with `fernapi/fern-python-sdk` 5.41.3's complete, comment-stripped output for it, generated by `tools/fern-goldens/fern-references.py generate measurements` for the `docs/fern-measurements/cases.tsv` case `handed-off/union-modelling/union-modelling/singleton-enum-tags`, under the shared Fern lock. `literals/fern-expected/` is the same document generated with `enum_type` unset (crozier's `literals` mode), registered as `…/singleton-enum-tags/literals`.

## The rule

A union whose members each tag one property with a typed one-member `enum` is discriminated on it, whether a member is a `$ref` requiring the tag or an inline object leaving it unrequired, and whether the tag is written inline or as a `$ref` to a one-member enum component; the same holds for a component map's value union, and the `$ref`ed models lose the tag field. (A `$ref` whose tag is unrequired still does not discriminate beside inline members.)

## The comparison

The certified pair writes `Author` as the `kind`-discriminated union `Author_Crew`, `Author_Contractor`, `Author_Autopilot`, `Author_Harbour`, and `CrewMember`/`Contractor` without `kind`. crozier wrote the inline members `AuthorTwo`/`AuthorThree` in a plain union and kept `kind` on both models (ironclad's `ActivityAuthorModel`). It also declares `Shipment` as the `mode`-discriminated union of `Lorry`, `Shipment_Rail` and `Shipment_Sea` (tags written `$ref ModeRoad`, …) and `ShipmentsByPort = Dict[str, ShipmentsByPortValue]` over the discriminated `ShipmentsByPortValue_Road`/`_Sea`, with no `mode` on `Barge`; crozier wrote plain unions there (Nussknacker's `NodeData` and `Map_TypingResultInJson`). Repaired in `inferred_discriminant_property` (which `inferred_strip_discriminant_property` now shares), `Builder::discriminated_union`, the component map arm of `Builder::add_named_shape` and `collect_discriminant_strips`. The enum components change in `literals` mode, so `literals/fern-expected/` is committed too. crozier now byte-matches `fern-expected/`.
