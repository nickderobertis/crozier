# A recursive JSON alias is named, so the models holding it import

**Kind:** `fern-defect`: generated modules that cannot be imported (#539, the
eleven Supabase model modules that hold its recursive `JsonValue` aliases). The
independently authored
[Signal Archive document](../../fern-measurements/type-lowering/recursive-json-alias/openapi.yml)
declares `JsonValue`, an `anyOf` of nullable scalars, an array of itself and a
map of itself, `Tree`, a label, an array of itself or a `Node` whose `children`
is a `Tree`, and a `Signal` model holding them as fields, as array items and as
map values. Both sides import `Node` in `tree.py` for type checkers only. Its unedited complete certified tree sits beside it as
`fern-expected/`, generated by Fern CLI 5.216.0 with `fernapi/fern-python-sdk`
5.42.0 through `fern-references.py generate measurements
type-lowering/recursive-json-alias` under the shared generation lock (packaged
preview layout, organization/package `fern`, project `default_package_name`,
`pydantic_config.enum_type: python_enums`); the literals tree is its
`expected-literals/` overlay.

The certified `src/fern/types/json_value.py` is the implicit recursive alias
`JsonValue = typing.Union[typing.Optional[JsonValueZero],
typing.List["JsonValue"], typing.Dict[str, "JsonValue"]]`. crozier writes the
same alias under `if typing.TYPE_CHECKING:`, names it through
`typing_extensions.TypeAliasType("JsonValue", …)` under `elif IS_PYDANTIC_V2:`,
and under `else:` (pydantic v1, which cannot validate a recursive alias) writes
it with each self-reference read as `typing.Any`.

A cycle made only of aliases is the same defect: the independently authored
[Assay Ledger document](../../fern-measurements/type-lowering/recursive-alias-cycle/openapi.yml)
declares `JsonValue-Output`, a union of a scalar, `JsonArray-Output` (an array
of it) and `JsonObject-Output` (a map of it), reached by `InferenceReport`, a
field of `RunSummary`. Its certified tree, generated the same way, writes
`JsonValueOutput` as the implicit alias over the quoted `"JsonArrayOutput"` and
`"JsonObjectOutput"`; crozier writes the three branches above, its pydantic v1
branch reading both quoted references as `typing.Any`.

## Executed certified-output evidence

With the SDK's HTTPX and Pydantic dependencies installed, execute the committed
[proof script](generated-model-imports.py) against each tree's `src/`:

```sh
python docs/departures/evidence/generated-model-imports.py \
  docs/fern-measurements/type-lowering/recursive-json-alias/fern-expected/src fern.types:Signal \
  '{"id": "a", "payload": {"k": [1, "x", null, {"n": true}]}, "history": [[1, 2], "y"], "labels": {"l": {"m": [3]}}, "tree": ["leaf", {"name": "n", "children": ["x", ["y"]]}]}' \
  invalid
```

Run on 2026-11-23 (Python 3.12, HTTPX 0.28.1), it printed under Pydantic
1.10.27 `{"failed": "no result within 30s"}` (pydantic expands the alias
without end) and under Pydantic 2.14.4 `{"pydantic": "2.14.4", "failed":
"RecursionError"}`, each exiting 0. That expansion grows by about 0.6 GB a
second, which exhausted a 16 GB CI runner before the time limit, so the script
now bounds the child's address space at 4 GiB where the platform enforces it:
run again on 2026-11-24 (Python 3.14, Linux) the certified tree prints
`{"pydantic": "1.10.27", "failed": "MemoryError"}` within ten seconds, still
exiting 0, and 2.14.4 is unchanged. Run the same way over crozier's generated
tree with `valid`, both construct the nested value:
`Signal(id='a', payload={'k': [1, 'x', None, {'n': True}]}, history=[[1, 2], 'y'], labels={'l': {'m': [3]}}, tree=['leaf', {'name': 'n', 'children': ['x', ['y']]}])`
under 1.10.27, and under 2.14.4 the same with the numbers read as floats and
the tree's node constructed as `Node(name='n', children=['x', ['y']])`.

Over the cycle (`fern.types:RunSummary`, payload `{"report": {"engine": "e",
"inference_diagnostics": {"a": [1, "x", null, {"b": [true]}], "c": {"d": 2.5}}},
"label": "l"}`), the certified tree printed `{"failed": "no result within 30s"}`
under Pydantic 1.10.26 and 1.10.27 (`MemoryError` under the bounded 1.10.27 run
of 2026-11-24), and `{"pydantic": "2.14.4", "failed":
"RecursionError"}` under 2.14.4; crozier's tree constructs
`RunSummary(report=InferenceReport(engine='e', inference_diagnostics={...}), label='l')`
under all three. (The naming-acceptance screen of the same shape saw the
certified tree crash the interpreter with SIGSEGV under 1.10.26 on its host;
the script reports such a death as `killed by signal 11`, also a failure; on
Windows, where an overflow ends the process with the NTSTATUS `0xC00000FD`
instead of a signal, as `killed by exception 0xC00000FD`.)

## The rule

`recursive_alias_named_type` admits only a `.py` type-alias module whose Fern
side is one alias naming itself or other aliases by quoted reference, and whose crozier side is Fern's imports plus
`typing_extensions` and the core's `IS_PYDANTIC_V2`, then exactly the three
branches above built from Fern's own alias target, compared with layout
dropped, the v1 branch reading at least one quoted reference as `typing.Any`
and keeping the rest. Any other change to the target, the imports or the
trailer still fails. The `type_lowering::recursive_alias_cycles_are_named`
journey holds the cycle's measurement. The `type_lowering::recursive_json_aliases_are_named` journey compares
the measurement's whole trees with the departure applied, and
`type_lowering::sdk_env_escaped_discriminators_and_recursive_aliases_import`
runs this script over both sides under both Pydantic majors.
