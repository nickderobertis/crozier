# An int64 example rounded past the format's bounds

The independently authored
[`odometer-reading`](../../openapi-surface/handwritten/odometer-reading/openapi.yml)
source posts a body whose `metres` property is `type: integer`, `format: int64`
with the example `9223372036854775807`, the int64 maximum, beside a
`trip_count` of the same format exampled `9007199254740993`; a `drift`
exampled with the int64 minimum and a `bias` exampled `-9007199254740993`; a
`checkpoints` array whose int64 items carry the maximum; and a required `depot`
query parameter, int64, exampled with the maximum too. Its complete
unedited certified tree was generated by Fern CLI 5.67.1 and
`fernapi/fern-python-sdk` 5.20.0 (packaged preview layout, organization and
package `fern`, project `default_package_name`, no audience filter,
`pydantic_config.enum_type: python_enums`); the companion overlay under
[`docs/fern-measurements/literals-mode/odometer-reading`](../../fern-measurements/literals-mode/odometer-reading/)
records the same source with `enum_type` unset.

Fern reads the document's numbers as JavaScript doubles, so every integer
example above 2^53 in magnitude is written as the double nearest it. For
`trip_count` and `bias` that is `9007199254740992` and `-9007199254740992`:
different integers than declared, but valid int64s, and crozier writes them
exactly as Fern does. For `metres`, `depot` and the `checkpoints` element the
nearest double is 2^63, which Fern spells `9223372036854776000` in the README,
`reference.md` and both client docstrings; for `drift` it is -2^63, spelled
`-9223372036854776000`. Each lies outside the int64 range the schema declares,
so the documented example is invalid for its own schema. crozier writes the
declared `9223372036854775807` or `-9223372036854775808` there instead and
nowhere else.

## Executed certified-output evidence

The committed [validator](int64-example-rounded-out-of-range.py) imports the
generated package, evaluates every worked call of the operation — the sync and
async client docstrings, both README usage blocks and the `reference.md`
example — binds each docstring call to the actual generated method with
`inspect.signature`, and checks each argument the source declares
`type: integer` with `format: int64` (a query parameter, a body property, or each element of a body
array whose items declare it) against the signed 64-bit bounds and the
declared example. It reads the document as JSON, fails the proof for an
operation it cannot find or one declaring no such example, and refuses a
document without the structure it reads as an input error (exit 2). Executed on 2026-10-11 with
Python 3.14 and PyYAML 6.0.3 from the repository environment:

```sh
python -c 'import json, sys, yaml; json.dump(yaml.safe_load(open(sys.argv[1])), sys.stdout)' \
  docs/openapi-surface/handwritten/odometer-reading/openapi.yml > /tmp/odometer-reading.json
PYTHONDONTWRITEBYTECODE=1 python docs/departures/evidence/int64-example-rounded-out-of-range.py \
  docs/openapi-surface/handwritten/odometer-reading/fern-expected /tmp/odometer-reading.json \
  --operation-id recordReading --method record_reading --examples invalid
```

It exited 0, reporting for each of the five calls:

```text
"bias": "in range", "checkpoints": "9223372036854776000 exceeds the int64 bounds (-9223372036854775808, 9223372036854775807)", "depot": "9223372036854776000 exceeds the int64 bounds (-9223372036854775808, 9223372036854775807)", "drift": "-9223372036854776000 exceeds the int64 bounds (-9223372036854775808, 9223372036854775807)", "metres": "9223372036854776000 exceeds the int64 bounds (-9223372036854775808, 9223372036854775807)", "trip_count": "in range"
```

The same command with `--examples valid` exits 1 on the certified tree. Over a
tree the compiled crozier binary generated from the same source
(`crozier --no-config generate python --spec … --package-name fern
--project-name default_package_name`) it exits 0 with `--examples valid`,
reporting `"the declared example, in range"` for `metres`, `drift`, `depot`
and `checkpoints` in every call; the literals tree reads the same.
`sdk_env_int64_example_validator_separates_fern_from_crozier` in
`crates/crozier-e2e/tests/e2e.rs` drives this validator over both trees, in
both directions, over a directory holding no package, an unknown operation and
a document stripped of its examples.

## The parity rule

The rule accepts one aligned line pair of `README.md`, `reference.md` or a
client docstring's `Examples`, equal but for one integer standing alone as a
keyword's value or a list's element, when crozier's value is an int64 example
the parsed source document declares, Fern's is the JavaScript spelling of that
value's nearest double, and Fern's lies outside the signed 64-bit range. Without the source document, for a value the
document does not declare, for an in-range rounding, or outside an example, it
does not apply. The line ledger is recorded from `src/parity.rs`, never
hand-edited.
