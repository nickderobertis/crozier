# OpenAPI surface coverage — feature combinations

Which combinations of two or more OpenAPI features crozier has to prove, beside
the single features the six region files enumerate. Two features that each
byte-match on their own can still diverge where crozier's handling of one
branches on the other, and that is where an unmeasured difference would first
reach a migrating user's SDK. This file is the reviewable list; the census
declares each selected combination and the region files classify it.

## The selection rule

A combination is **selected** when one of two kinds of evidence admits it:

- **a crozier branch that reads both features**: a function of `src/ir.rs`,
  `src/emit.rs`, `src/naming.rs`, `src/refs.rs` or `src/openapi.rs` whose
  condition reads the two features together, so that a document combining them
  takes a path that a document with either one alone does not. The `why` cell
  names it as `src/<file>.rs::<function>`, with the arm in words; or
- **real-specification co-occurrence of features whose handling can interact**:
  registered or acquired real specifications combine the two at one site, and
  the `why` cell says where crozier's lowering of one meets the other's. Every
  count is reproducible: the registered corpus's from `just surface-census
  --selector '<selector>'` over the 256 registered golden sources, and the
  acquired pool's from `just witness-search-local-census` over the APIs.guru
  `openapi-directory` archive at commit
  `f04b8d0bcd39c52e1cf3ad7a5fe744709832ae49`, the revision the corpus's
  APIs.guru searches pinned, whose 4,138 JSON and YAML entries read as 1,970
  OpenAPI 3 documents.

The original population measurements give both counts. Additional candidates
admitted by a code branch name that branch directly; their region rows record
the registered-corpus counts, without claiming an acquired-pool measurement.

A candidate is **rejected** when neither kind of evidence admits it, or when an
existing census row already separates the documents that take the branch from
the ones that do not — a combination that row's own selector or fixture already
distinguishes would be a second answer to one question. A rejected candidate is
listed under `## Rejected` with its reason, so the review can see everything that
was weighed. The research audits the five Rust modules for branches where one
feature changes another's handling, and records the resulting candidates here
in crozier's own terms. Selected selectors have registered-corpus measurements;
acquired-pool counts are recorded where measured, rather than inferred for
code-admitted candidates. There is no limit on how many are selected: a long
list is split across proof work by `seam`, never trimmed.

**How a combination is spelled.** Each is a conjunction of the census's selector
grammar, with `&`, `>`, `~>` and `!` meaning exactly what they mean for every
other conjunction.
The first grammar extension adds seven **request-body readings
of an Operation Object**, member-only exactly as the pointer-walk readings are.
A request body's media types are the *keys* of its `content` map, which the walk
reads as names rather than fields, and whether a body property shares its name
with a parameter is a comparison between two subtrees of one operation that no
member at either end can make. So `operation.requestBody:json-media`,
`:multipart-form-media`, `:form-urlencoded-media` and `:octet-stream-media` read
which media types the operation's request body offers, and
`operation.requestBody:property-named-as-path-parameter`, `-query-parameter` and
`-header-parameter` read whether one of its parameters — declared on it or on its
Path Item — has the same `name` as a property of a schema its request body writes.
None is a selector on its own: each is matchable only as a member beside the
feature it is combined with, so it adds no single-feature row.

The operation-context extension joins a document's version and security defaults
with an operation's grouping and overrides, and reads response status-map keys
and media alternatives at that operation through member-only
`operation.context:*` readings. Success readings use the same selected response as the
existing census success predicates; media alternatives belong to that response.
Error readings inspect 4xx and 5xx responses, resolving local component responses
and schemas. The different-schema reading compares declarations across operations
at the same written error status; it deliberately measures candidate sites rather
than claiming that their converted exception types differ. No new standalone
single-feature selector is introduced.

**What the list holds and what it does not.** `key`, `selector` and `region`
restate the census's `COMBINATIONS` declaration in
`tools/surface-census/openapi-surface-census.py`, which is their one source; a
drift test in `tools/surface-census/tests/surface_census_test.py` fails when this
table, that declaration, the region rows or `witness-search-keys.tsv` part. A
row's `region` is the region of the object its conjunction anchors on. Its
`seam` is the generator code its byte-match proof most exercises — one of
`examples`, `models-unions-refs`, `parameters`, `bodies-responses` and
`naming-clients` — and its `owner` follows from the seam:
`prove-schema-combinations` for `examples` and `models-unions-refs`,
`prove-operation-combinations` for the other three. The list holds no proof
status: whether a combination is proven is its region row's category.
