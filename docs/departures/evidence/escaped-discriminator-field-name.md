# A discriminator naming an escaped tag field writes the field, not the wire name

**Kind:** `fern-defect`: a generated module that cannot be imported (#925). The
independently authored
[Costume Store document](../../fern-measurements/type-lowering/inferred-discriminator-tags/openapi.yml)
declares `QueryResponse`, a `oneOf` of `QueryResult` and `QueryStatus`, each
tagging itself with a one-value `schema` enum. `schema` is a name pydantic's
`BaseModel` already holds, so both Fern and crozier declare each variant's tag
as the field `schema_` aliased to `schema`. Its unedited complete certified
tree sits beside it as `fern-expected/`, generated by Fern CLI 5.216.0 with
`fernapi/fern-python-sdk` 5.42.0 through `fern-references.py generate
measurements type-lowering/inferred-discriminator-tags` under the shared
generation lock (packaged preview layout, organization/package `fern`, project
`default_package_name`, `pydantic_config.enum_type: python_enums`); the
literals tree is its `expected-literals/` overlay.

The certified `src/fern/types/query_response.py` closes the union with
`pydantic.Field(discriminator="schema")`, the wire name, which no variant
declares as a field. crozier writes `pydantic.Field(discriminator="schema_")`,
every other byte of the line Fern's.

## Executed certified-output evidence

With the SDK's HTTPX and Pydantic dependencies installed, execute the committed
[proof script](generated-model-imports.py) against each tree's `src/`:

```sh
python docs/departures/evidence/generated-model-imports.py \
  docs/fern-measurements/type-lowering/inferred-discriminator-tags/fern-expected/src \
  fern.types:QueryResponse '{"schema": "store.status.v1", "scope_id": "s", "status": "ready"}' invalid
```

Run on 2026-11-22 (Python 3.12, HTTPX 0.28.1), it printed under Pydantic
1.10.27 `{"pydantic": "1.10.27", "failed": "ConfigError"}` and under Pydantic
2.14.4 `{"pydantic": "2.14.4", "failed": "PydanticUserError"}`, each exiting 0:
the module raises on import, "Model 'QueryResponse_StoreQueryV1' needs a
discriminator field for key 'schema'". Run the same way over crozier's
generated tree with `valid`, Pydantic 2.14.4 prints
`{"pydantic": "2.14.4", "constructed": "QueryResponse_StoreStatusV1(schema_='store.status.v1', scope_id='s', status=<QueryStatusStatus.READY: 'ready'>)"}`.
Under Pydantic 1.10.27 crozier's module imports; `pydantic.parse_obj_as` over
the wire payload returns the same variant, while the SDK core's own
`parse_obj_as`, which renames the payload's keys to field names before pydantic
reads them and is shared byte for byte with Fern's runtime, reports
`ValidationError` (the drafted follow-up on the core's v1 dealiasing).

## The rule

`escaped_discriminator_field_name` admits only a generated `.py` line whose
sole change replaces `discriminator="<name>_"` with `discriminator="<name>"`,
where `<name>` is a property the source document declares whose model field
crozier escapes with a trailing underscore. Any other change on the line, or a
name the source does not declare that way, still fails. The
`type_lowering::inferred_tags_discriminate_and_name_the_variant_field` journey
compares the measurement's whole trees with the departure applied, and
`type_lowering::sdk_env_escaped_discriminators_and_recursive_aliases_import`
runs this script over both sides under both Pydantic majors.
