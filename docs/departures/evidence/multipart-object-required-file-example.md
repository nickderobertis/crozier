# Multipart object examples omit a required file

Two independently authored sources retain the exact combinations:
[an aliased object](../../openapi-surface/handwritten/multipart-alias-object/openapi.yml)
and [an object argument named `json`](../../openapi-surface/handwritten/multipart-json-module/openapi.yml).
Their unedited complete certified trees sit beside them. Each uses Fern CLI
5.67.1, `fernapi/fern-python-sdk` 5.20.0, packaged preview layout,
organization/package `fern`, project `default_package_name`, no audience filter
and `pydantic_config.enum_type: python_enums`. The separate certified literals
trees use those same sources with `enum_type` unset.

The alias method takes `plan: PlanAlias` and `attachment: core.File`; its
client docstring constructs `Plan(bearing=1)` but omits `attachment`. The
JSON-named method takes `json: StoreSurveyRequestJson` and the same required
file; its client docstring omits that file too. Both sync and async examples
fail binding. The README and reference examples already include the file and
remain unchanged.

## Executed certified-output evidence

With the SDK's HTTPX/Pydantic dependencies installed, execute the committed
[proof script](multipart-object-required-file-example.py):

```sh
python docs/departures/evidence/multipart-object-required-file-example.py \
  docs/openapi-surface/handwritten/multipart-alias-object/fern-expected/src \
  alias --examples invalid --wire
python docs/departures/evidence/multipart-object-required-file-example.py \
  docs/openapi-surface/handwritten/multipart-json-module/fern-expected/src \
  json --examples invalid --wire
```

Both commands exited 0 in Python 3.14. Their literals counterparts, using
`docs/fern-measurements/bodies-responses/<shape>-literals/fern-expected/src`,
also exited 0 with the same binding failures and passing wire assertions. Each imported the actual certified
package, decoded its actual sync/async requests through local HTTP transports,
verified the encoded object and binary file, and bound the docstring's parsed
call arguments to `inspect.signature` of its actual generated method. Each
owned sync and async binding reported `missing a required argument:
'attachment'`. The adjacent `store_metadata` examples bind correctly; its
requests use the unaliased json module beside the other method's `_json`.

Thus the JSON encoding and aliased module are valid behavior to match. The
fault is exactly the docstring's missing required file. Crozier adds only that
argument. The same script, with `--examples valid --wire`, is driven against
SDKs generated by the compiled crozier binary; it verifies corrected binding,
actual wire values and recovery from a missing-file call. The parity rule
requires a matching generated multipart method and the exact file placeholder,
preserves nested object constructor arguments, and rejects adjacent unexplained
changes. The line ledger is recorded from `src/parity.rs`, never hand-edited.
