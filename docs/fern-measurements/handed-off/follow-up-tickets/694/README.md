# One owner for a shared package export

Issue [#694](https://github.com/nickderobertis/crozier/issues/694).
`openapi.yml` was authored from scratch: a fleet-creation body holds an array
of two named sensor alternatives, also used by its nested sensors client.
The alternatives are untagged so this reduction isolates ownership from
discriminator lowering.

`fern-expected/` is the complete, untouched comment-stripped tree freshly
generated by Fern CLI 5.163.1 with `fernapi/fern-python-sdk` 5.41.3, through
`tools/fern-goldens/fern-references.py::run_fern` and `strip_into`, using the
workspace of `generate-fern-fixture.sh`, under the shared generation lock.
`fern.log` and `exit-code` record the successful run. No enum declaration
changes output between modes.

At the base, `crozier compare` names only `src/fern/fleets/__init__.py`:
crozier exports `FixedSensor` and `MobileSensor` from both `.types` and
`.sensors`, duplicating the lazy-map keys and `__all__` entries. Fern exports
each through `.sensors` once. `emit::tag_pkg_init_file` now removes a child's
exported names from the parent's own import block before constructing any
of those three surfaces.

Verdict: **parity-gap-repaired**. `crozier compare` byte-matches the complete
tree with the catalogued SDK identity headers applied. The unit test
`a_parent_exports_a_shared_type_from_its_child_once` and real CLI comparison
`follow_up_ticket_matching_outputs_hold_against_the_certified_pair` hold it.
