## The document

## The comparison

The record's three rules, measured: (1) the README and `reference.md` client constructions pass `tenant_code="<X-Tenant-Code>"` alone; the pair leaves the boolean, integer and number headers out. (2) Each top-level value of the free-form body's schema example is printed on one line in both Markdown files, whatever its width. (3) `reference.md`'s worked calls pass `codes_array=[` and `ids_array=[`, while the generated methods take `codes` and `ids`, and its parameter list spells `**codes_array:**`. crozier added the two non-string headers and wrapped the long values (rules 1 and 2), and already passed `codes=`/`ids=` (rule 3).

**Verdict: `fern-defect-departed` (`bracket-query-parameter-call-keyword`).** Rules 1 and 2 were parity gaps, repaired in `src/emit.rs` (`documentation_client_example_args` passes only string and date headers; `build_example_inner` flattens a free-form schema example's top-level values in the Markdown writers). Rule 3 is a standing-kind Fern defect, an example that does not match the signature: `runtime.txt`'s `bracket-query-parameter-call-keyword` sections record the certified SDK's `reference.md` calls failing to bind (`TypeError: got an unexpected keyword argument 'codes_array'`, and `'ids_array'`, sync and async) and crozier's binding and sending the values under the `[]` wire names. crozier keeps the method's own keyword as the catalogued departure ([evidence](../../../../departures/evidence/bracket-query-parameter-call-keyword.md)); the parameter list stays matched. A fourth difference sits beside the cause, in the client docstrings: the pair constructs the client with `strict_mode="YOUR_STRICT_MODE"`, `shift_number="YOUR_SHIFT_NUMBER"` and `tide_metres="YOUR_TIDE_METRES"` against `bool`, `int` and `float` annotations, a `YOUR_*` placeholder for a non-string type, the standing Fern-defect kind crozier had copied. On the manager's ruling it is catalogued here: crozier passes the generator's own placeholder for the declared type, `strict_mode=True`, `shift_number=1` and `tide_metres=1.1`, and keeps `tenant_code="YOUR_TENANT_CODE"`, as the `non-string-client-header-example` departure ([evidence](../../../../departures/evidence/non-string-client-header-example.md)), following the catalogued `date-header-constructor-example`. `runtime.txt` records the certified docstring values failing strict validation against the actual constructor's annotations and reaching the wire as `YOUR_*` header values, and crozier's validating and arriving as `True`, `1` and `1.1` at a local HTTP server.

With both departures applied, crozier's tree byte-matches `fern-expected/`.
