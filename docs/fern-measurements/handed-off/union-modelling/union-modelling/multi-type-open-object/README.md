# union-modelling: multi-type-open-object

A sub-case of the [`union-modelling`](../README.md) cause; **verdict: parity-gap-repaired**.

`openapi.yml` was authored from scratch for this rule. `fern-expected/` is Fern CLI 5.163.1 with `fernapi/fern-python-sdk` 5.41.3's complete, comment-stripped output for it, generated by `tools/fern-goldens/fern-references.py generate measurements` for the `docs/fern-measurements/cases.tsv` case `handed-off/union-modelling/union-modelling/multi-type-open-object`, under the shared Fern lock. The enum mode changes nothing here but `core/enum.py` and `.fern/metadata.json`, so no `literals/` tree is committed.

## The rule

A property whose `type` lists `object` and `array` (with or without `null`) beside `additionalProperties` is Fern's hoisted `{Owner}{Prop} = typing.Union[typing.Dict[str, typing.Any], typing.List[typing.Any]]`: the `additionalProperties` describes the `object` member only.

## The comparison

The certified pair declares `BatchReceiptDetails` and `UnprocessableEntityErrorBodyContext` and types the fields `typing.Optional[…]` of them; crozier typed both `typing.Optional[typing.Dict[str, typing.Any]]` (gecko's and numbat's error-body `extra`). Repaired in `openapi::normalize_multi_type_schemas`. crozier now byte-matches `fern-expected/`.

Held by `union_modelling_sub_rules_match_the_certified_pair` in `crates/crozier-e2e/tests/e2e/union_modelling.rs`, which byte-compares crozier's SDK for this document with `fern-expected/` (apart from the catalogued departures the ledger records) and requires the pre-repair spelling to fail that comparison, and by the unit test `a_multi_type_list_lends_its_additional_properties_to_the_object_member` in `src/ir.rs`'s `union_modelling_tests`.
