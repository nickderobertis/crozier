# Binary form parts in worked calls

**Kind:** `fern-defect`. Measured at Fern CLI 5.216.0 / fern-python-sdk 5.42.0.

A multipart part that references a binary string component is the method's
`bytes` alias parameter. The measurement
[`multipart-binary-required-part`](../../fern-measurements/bodies-responses/multipart-binary-required-part/)
requires such a part: its `fern-expected/` tree, generated by the certified
pair, declares `FormFile = bytes` (`src/fern/types/form_file.py`) and
`def upload_log(self, *, file: FormFile, ...)`, and every worked call passes
the string sample `file="file"` — `README.md` lines 43 and 74, `reference.md`
line 24, `src/fern/uploads/client.py` lines 56 and 148.

**Fern's calls do not type-check.** Every worked example of the tree (the
Markdown fences and the docstring `Examples` sections, each its own module),
checked by pyright 1.1.408 in basic mode against the tree's own `src/`:

```text
$ npx -y pyright@1.1.408 .   # the extracted examples of fern-expected/
s0001_README.py:6:10 - error: Argument of type "Literal['file']" cannot be assigned to parameter "file" of type "FormFile" in function "upload_log"
    "Literal['file']" is not assignable to "bytes" (reportArgumentType)
... the same for the async README call, reference.md and both docstrings
5 errors, 0 warnings, 0 informations
```

crozier passes the same sample as bytes, `file=b"file"`, in all five places,
and the same check over crozier's tree for the document reports `0 errors`.
Everything else — the annotation, the multipart encoding, the optional part
`transcribe_recording` leaves out — matches the certified tree.

The line rule admits only a line where Fern passes `name="<sample>",` and
crozier `name=b"<sample>",` at the same indent, for a parameter some generated
raw client annotates `bytes`, an `Optional` of it, or an alias chain ending in
it, in `README.md`, `reference.md` or a `client.py`; a JSON body's `request`
stays `binary-json-body-example`'s. Its unit test rejects another sample, a
non-bytes parameter, another file and a shifted indent.
`bodies_responses::required_binary_reference_part_is_exampled_as_bytes` holds
the untouched tree to the certified one under the ledger, which pins every
occurrence.
