# `readme-client-class-casing`

**Kind:** `fern-defect`. Fern's README imports a client class the generated
package does not define, so the snippet's own import fails.

## The input

[`readme-client-class-casing/openapi.yml`](readme-client-class-casing/openapi.yml),
a crozier-authored document with one `POST` operation, generated by Fern with the
organization `LanternHarbor` and no `client_class_name`.

## Fern's output

Fern CLI 5.67.1 with `fernapi/fern-python-sdk` 5.20.0 (the certified pair), a
`fern/fern.config.json` of `{ "organization": "LanternHarbor", "version":
"5.67.1" }` and this `fern/generators.yml`:

```yaml
api:
  path: openapi/openapi.yml
groups:
  python-sdk:
    generators:
      - name: fernapi/fern-python-sdk
        version: 5.20.0
        config:
          pydantic_config:
            enum_type: python_enums
        output:
          location: local-file-system
          path: ../generated/python
```

`fern generate --group python-sdk --local --force` (no `FERN_TOKEN`, so the flat
layout) exits 0 and writes the tree committed, comment-stripped as every
committed Fern tree is, in
[`readme-client-class-casing/fern-reference/`](readme-client-class-casing/fern-reference/).

The code defines `LanternHarborApi`, `AsyncLanternHarborApi` and
`LanternHarborApiEnvironment` (`client.py`, `environment.py`). The README's
first snippet imports `LanternHarborApi`, but every later one lowers the inner
capital — `LanternharborApi`, `AsyncLanternharborApi`,
`LanternharborApiEnvironment` — on lines 52–53, 55–56, 67, 69, 104, 106, 148,
150, 165 and 167, and `reference.md` does the same for the environment class on
lines 16 and 19.

## Why it is a defect

With the tree installed as the package `LanternHarbor` beside `httpx` and
`pydantic`:

```text
$ python -c "from LanternHarbor import AsyncLanternharborApi"
ImportError: cannot import name 'AsyncLanternharborApi' from 'LanternHarbor' (…/LanternHarbor/__init__.py). Did you mean: 'AsyncLanternHarborApi'?
$ python -c "from LanternHarbor.environment import LanternharborApiEnvironment"
ImportError: cannot import name 'LanternharborApiEnvironment' from 'LanternHarbor.environment' (…/LanternHarbor/environment.py). Did you mean: 'LanternHarborApiEnvironment'?
$ python -c "from LanternHarbor import AsyncLanternHarborApi; print(AsyncLanternHarborApi.__name__)"
AsyncLanternHarborApi
```

The README's examples name classes the package does not define, so they
contradict the generated code: docs or examples that contradict the generated
code are a defect under the defect rule.

## crozier's output

`crozier generate python --spec openapi.yml --layout flat --package-name
LanternHarbor --project-name LanternHarbor` writes the same tree but for those
lines, where it names the classes its code defines (`LanternHarborApi`,
`AsyncLanternHarborApi`, `LanternHarborApiEnvironment`). `crozier compare` over
the two reports each such line as this departure and matches; the
`compare_reports_the_readme_casing_departure_and_fails_on_any_other_difference`
journey in `tests/e2e/compare.rs` drives exactly that, and the tree's
`readme-client-class-casing` rows in `tests/fixtures/departures-ledger.tsv` are
the lines above (its other rows are the client wrapper's
`sdk-identity-header-prefix` lines).
