## How the search ran

The manager's screening bound ordered the work:

1. **Licence first.** Every code-search and Sourcegraph declarer's repository licence was read at the document's own commit (`GET /repos/{owner}/{repo}/license?ref=<commit>`, 5509 repository-and-commit pairs, all through the guard), beside the document's own `info.license`, against [`../../corpus-licensing.md`](../../corpus-licensing.md). APIs.guru declarers carry the first pass's reading.
2. **Instrumented probe of the arm and combination declarers.** Every admissible code-search and Sourcegraph declarer of an arm or interaction-branch target ran through the branch's instrumented crozier (built from `src/` as it stands at `43b1bde19`, `golden-reach-search.py`'s `_probe_one`, `ruff` replaced by a pass-through, 120 seconds each): 5571 documents. The registered and APIs.guru declarers carry the first pass's base run.
3. **Certified-pair screens, round-robin.** Each target's admissible declarers were screened smallest first, every target's smallest before any target's second, through the script `just fern-goldens-generate` wraps, `tools/fern-goldens/generate-fern-fixture.sh <fixture> 5.41.3 <spec>` (the recipe generates only registered rows, and a candidate is not one until it matches), under the shared `fern-generation.lock`, one generation at a time, then compared whole with `crozier compare`: 118 generations — 26 byte-match whole, 60 differ, 31 refused by the certified pair, 1 not finishing. A byte-match that declares the target's complete trigger was registered.
4. **GitHub code search** for every target the on-host populations left with no admissible declarer the certified pair generates from, each query and what it returned in [`code-search.tsv`](code-search.tsv); its acquisitions were licence-read, detected and, for arm targets, probed, and every target they gave an admissible declarer had its smallest one screened.

Screening ran from 03:27 to 06:06 UTC on 2026-10-31. The first round (every target's smallest admissible declarer) was complete by then, and the second and third had begun for most targets when screening stopped, well inside the six further hours the bound allows. The arm declarers among the last code-search acquisitions were probed afterwards; their one target with no screened declarer, `format-int64`, had its smallest already screened. 

## Detectors

Every document was read twice: by the census (`tools/witness-search/witness-search-local-census.py` over each target's selector) and by a complete-trigger detector where the selector is broader than the row's shape.

- **A feature row** is declared where its census selector in [`../witness-search-keys.tsv`](../witness-search-keys.tsv) counts a site. Where that selector is a single broad field (`schema.allOf`, `schema.description`, …), the declarer is a document holding the row's complete trigger, read off the parsed document by the detector tabled below; each detector fires on the row's own hand-written fixture.
- **An arm** is declared where the golden row's selector in [`../golden-reach-sites.tsv`](../golden-reach-sites.tsv) counts a site **and** an instrumented `crozier generate` over the document executes the arm, read with `golden-reach-search.py`'s own `_probe_one` against the base's instrumented build. The run gave each document 90 seconds and replaced `ruff` with a pass-through, which leaves crozier's own regions as they run; a document that timed out or that crozier refused gives no reading and stays outstanding.
- **A combination** is declared where its conjunction counts a site and the instrumented run executes every interaction site its `golden-reach-sites.tsv` row names.

The base's instrumented run covered the registered and APIs.guru populations whole; this pass probed every admissible code-search, Sourcegraph and newly acquired declarer of an arm or combination the same way (step 2 above). ### Root causes

- <a id="allof-member-description-docstring"></a>`allof-member-description-docstring`: An inline response schema written as an `allOf` of inline members, the last of which carries a `description`: crozier gives the merged model that description as its docstring, Fern gives it none.
- <a id="allof-oneof-inline-member-consts"></a>`allof-oneof-inline-member-consts`: A component that is an `allOf` of an open object and a `oneOf` of inline objects whose properties carry `const` values: Fern hoists each const as a single-value enum (`DestinationStripeConfigApiVersion`, …), crozier hoists none.
- <a id="blank-description-enum-docstring"></a>`blank-description-enum-docstring`: An inline enum written `description: ''`: Fern gives the enum class an empty docstring block (`""" """`), crozier gives it none.
- <a id="byte-text-response-reference-snippet"></a>`byte-text-response-reference-snippet`: An operation whose success response is `text/plain` with `type: string, format: byte`: Fern's `reference.md` gives its usage as the bare `client.….run_build(...)`, crozier writes the whole snippet.
- <a id="const-tag-variants-undiscriminated"></a>`const-tag-variants-undiscriminated`: An object schema with `properties` and a `oneOf` of `$ref` variants that each fix the tag property with a `const`, and no `discriminator`: Fern keeps the variants as plain models with a literal enum per tag (`CatPetType`), crozier infers a discriminated union (`Pet_Cat`, `Pet_Dog`).
- <a id="crozier-invalid-duplicate-parameter"></a>`crozier-invalid-duplicate-parameter`: An operation whose generated method would name one parameter twice: Fern generates valid Python, crozier's output fails to parse (`Duplicate parameter "title"`), so crozier generates nothing.
- <a id="crozier-refuses-boolean-schema"></a>`crozier-refuses-boolean-schema`: A 3.1 boolean schema (`true` or `false`) as a composition member: crozier fails to parse the document, Fern generates it.
- <a id="crozier-refuses-component-link-ref"></a>`crozier-refuses-component-link-ref`: A response `links` entry that is a `$ref` to `#/components/links/…`: crozier refuses the document as an unresolved reference, Fern ignores links and generates.
- <a id="crozier-refuses-dangling-component-ref"></a>`crozier-refuses-dangling-component-ref`: A `$ref` naming a component the document does not declare: crozier refuses the document, Fern generates around it.
- <a id="crozier-refuses-nullable-error-extension"></a>`crozier-refuses-nullable-error-extension`: crozier refuses a document whose response schema extends a `nullable` component through `allOf` while a response example omits a property the extension requires; Fern generates it.
- <a id="crozier-refuses-path-pointer-ref"></a>`crozier-refuses-path-pointer-ref`: A `$ref` that points into `#/paths/…` (a response header defined on another operation): crozier refuses the document as an unresolved reference, Fern resolves it and generates.
- <a id="crozier-refuses-path-without-slash"></a>`crozier-refuses-path-without-slash`: A path key without a leading `/`: crozier refuses the document (`path-without-leading-slash`), Fern generates it.
- <a id="crozier-refuses-type-name-collision"></a>`crozier-refuses-type-name-collision`: Two schemas lowering to one type name in different namespaces: crozier refuses the document (`type-name-collision`), Fern generates it.
- <a id="crozier-refuses-unknown-type-value"></a>`crozier-refuses-unknown-type-value`: A `type` written with a value crozier's type field does not admit: crozier fails to parse the document, Fern generates it.
- <a id="crozier-refuses-unreferenced-path-parameter"></a>`crozier-refuses-unreferenced-path-parameter`: An operation declaring a path parameter its path template does not name: crozier refuses the document (`path-parameter-unreferenced`), Fern generates it.
- <a id="digit-leading-schema-name"></a>`digit-leading-schema-name`: A component name beginning with a multi-digit number: Fern spells the whole leading number in words (`401Response` → `FourHundredOneResponse`), crozier spells only its first digit (`Four01Response`).
- <a id="example-empty-array-field"></a>`example-empty-array-field`: A request model whose example holds an empty array for an optional field: Fern's snippet leaves the field out (`Where()`), crozier passes it (`Where(or_=[])`).
- <a id="example-inline-union-member-constructor"></a>`example-inline-union-member-constructor`: A request example whose element matches an inline object member of a union: Fern writes that member's model constructor (`SelectedFulfillmentOptionZero(type=…)`), crozier writes a dict literal.
- <a id="example-map-of-model-values"></a>`example-map-of-model-values`: A request example whose map values are objects of a referenced model: Fern writes each value as that model's constructor (`FilterRange(gte=…)`), crozier as a dict literal.
- <a id="example-matching-union-variant"></a>`example-matching-union-variant`: A media-type example whose value for an undiscriminated `oneOf` property fits a later variant: Fern's snippet builds the variant the example fits (`SignedBundleV2`), crozier builds the first variant.
- <a id="falsy-property-example"></a>`falsy-property-example`: A property whose `example` is falsy (`""`, `0`): Fern discards it and writes its synthesized placeholder (`"bucket"`, `1000000`), crozier writes the falsy value.
- <a id="geo-json-success-media"></a>`geo-json-success-media`: A success response whose JSON media type is `application/geo+json`: Fern parses it as the JSON model, crozier returns `_response.text`.
- <a id="inline-response-union-variant-naming"></a>`inline-response-union-variant-naming`: An inline success-response union of two inline objects: the two name its hoisted variant models differently (Fern `…ResponseZero`, `…ResponseComputedAt`; crozier `…Response_`, `…ResponseScorecardSnapshotUnavailable`).
- <a id="inline-union-hoisting"></a>`inline-union-hoisting`: Inline unions in array items and map values: crozier hoists named union models (`AllowedToolChoiceToolsItem`, `CreateResponseBodyMetadata`) that Fern writes inline.
- <a id="json-binary-body-snippet"></a>`json-binary-body-snippet`: An `application/json` request body whose schema is `type: string, format: binary`: Fern's snippet passes `"string"`, crozier's passes `b"string"`.
- <a id="map-body-media-example"></a>`map-body-media-example`: A JSON request body whose schema is a map and whose media type carries an `example`: Fern's snippet writes the example's entries, crozier writes the placeholder `{"key": "value"}`.
- <a id="map-body-placeholder-layout"></a>`map-body-placeholder-layout`: A required JSON body that is a `$ref` to a map component and has no example: both write the placeholder `{"key": "value"}`, Fern on one line, crozier spread over three.
- <a id="map-value-union-hoisting"></a>`map-value-union-hoisting`: A map whose values are an `allOf`/`oneOf` composition: the two hoist different value models (crozier adds `MapAllofOneofStringifiedValue`, Fern adds `TripleNestedMapSchemaItemItemValue`).
- <a id="mistyped-scalar-example"></a>`mistyped-scalar-example`: A scalar property whose `example` has another JSON type than its schema's `type` (a string example on `type: number`, an integer on `type: string`): Fern discards the example and writes its synthesized placeholder, crozier writes the example value.
