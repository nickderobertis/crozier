# A field's wire alias is written as Python, not as the declared name

**Kind:** `fern-defect`: a generated package whose model cannot be imported,
and a model that, when run, reads and writes a field under a name the document
does not declare (#842). The independently authored
[Signal Relay document](../../fern-measurements/handed-off/follow-up-tickets/842/openapi.yml)
declares three `Beacon` properties: `relay\"code` (a backslash, then a quote),
`a" + bearing + "` (a balanced expression), and the plain control `call-sign`.
Its unedited complete certified tree sits beside it as `fern-expected/`,
generated by Fern CLI 5.200.0 with `fernapi/fern-python-sdk` 5.41.25 through
`fern-references.py generate measurements handed-off/follow-up-tickets/842`
under the shared generation lock (packaged preview layout, organization/package
`fern`, project `default_package_name`, `pydantic_config.enum_type:
python_enums`).

The certified `src/fern/types/beacon.py` writes each name between quotes
unescaped, then formats it: `FieldMetadata(alias='relay"code')` (line 13),
whose value has lost the backslash, and
`FieldMetadata(alias="a" + bearing + "")` (line 16), an expression over an
undefined name, each beside the same `pydantic.Field(alias=…)`. Fern's own lint
ignores undefined names (`F821`), so the generation succeeds. The earlier
[escaped-quote control](../../fern-measurements/handed-off/follow-up-tickets/679-escaped-quote-control/openapi.yml)
of #679 declares `probe\"code`, and its certified tree writes
`alias='probe"code'` the same way. crozier writes `alias='relay\\"code'`,
`alias='a" + bearing + "'` and `alias='probe\\"code'`, each the declared name as
data. Names whose unescaped literal Fern's ruff rejects (a lone quote, a line
break, a malformed escape) remain the `generator-lint-failure` refusal of #679
in both modes.

## Executed certified-output evidence

With the SDK's HTTPX and Pydantic dependencies installed, execute the committed
[proof script](escaped-field-alias-literal.py) against each certified tree:

```sh
PYTHONDONTWRITEBYTECODE=1 python docs/departures/evidence/escaped-field-alias-literal.py \
  docs/fern-measurements/handed-off/follow-up-tickets/842/fern-expected/src \
  --model fern.types.beacon:Beacon --wire 'relay\"code' --wire 'a" + bearing + "' \
  --wire call-sign --expected invalid
PYTHONDONTWRITEBYTECODE=1 python docs/departures/evidence/escaped-field-alias-literal.py \
  docs/fern-measurements/handed-off/follow-up-tickets/679-escaped-quote-control/fern-expected/src \
  --model fern.types.reading:Reading --wire 'probe\"code' --expected invalid
```

Run on 2026-11-17 (Python 3.14.7, HTTPX 0.28.1, Pydantic 2.13.5), each exited 0
and printed, in order:

```text
{"import": "SchemaError importing fern.types.beacon"}
{"aliases not declared": ["('probe\"code', 'probe\"code')"]}
```

Importing the certified `Beacon` fails: Pydantic cannot build the model, because
its alias is an expression over `bearing` rather than a string (run the same
way under Python 3.12 and 3.13, the import raises `NameError: name 'bearing' is
not defined`). The control's
certified `Reading` imports, but its alias is `probe"code`, not the declared
`probe\"code`, so a payload carrying the declared name never fills the field and
a written model sends the other name. Run the same way over crozier's tree with
`--expected valid`, `Beacon` imports, each field's two aliases are exactly one
declared name, and a payload keyed by the three declared names parses, dumps by
alias and converts for the wire under exactly those names
(`{"round trip": ["a\" + bearing + \"", "call-sign", "relay\\\"code"]}`).

## The rule

`escaped_field_alias_literal` admits only a generated `.py` line whose sole
change replaces each `alias=` literal of a declared property name holding a
quote or a backslash with Fern's spelling of that name: the name between double
quotes verbatim, or, where that is one string literal, the literal `ruff format`
writes for the value Python reads from it. A name the source does not declare, a
plain alias, any other change on the line, and the Markdown files still fail.
The unit test `escaped_field_aliases_admit_only_a_declared_name_spelled_as_its_value`
holds those cases; the follow-up ticket journeys compare both measurements'
whole trees with this departure applied, and
`sdk_env_wire_aliases_are_literal_data_in_crozier_and_not_in_the_certified_pair`
runs this script over both sides.
