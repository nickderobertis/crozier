# SDK variable documentation

The independently authored [Signal Observatory input](../../openapi-surface/handwritten/observatory-client-variable/openapi.yml)
declares `stationCode` as a string SDK variable and uses it in a path parameter.
Its complete comment-stripped output was generated by CLI 5.67.1 and
`fernapi/fern-python-sdk` 5.20.0, packaged layout, organization `fern`, client
class `FernApi`, `python_enums`, extra fields `allow`, default retries 2, and no
audience filter.

The generated constructor requires keyword `station_code`; `list_signals`
takes only keyword `request_options`. README constructor calls omit the required
field, method calls retain a positional placeholder, and reference.md documents
`station_code` under the method.

Run `python3 docs/departures/evidence/sdk-variable-docs-examples.py`. It executes
the certified output signatures with annotations and bodies removed, then uses
`inspect.signature.bind` on the documented calls. The constructor reports
`missing a required argument: station_code`; the method reports `too many
positional arguments`. This establishes a signature defect without importing
unrelated optional runtime dependencies.

The rule applies only to documentation for methods whose generated route reads
a lifted client field. It removes the matching parameter block and positional
placeholder and supplies that field to constructor examples. Every remaining
line must match. `sdk_variable_documentation_departure_rejects_an_adjacent_mismatch`
proves that changing the adjacent reference title still fails comparison.
