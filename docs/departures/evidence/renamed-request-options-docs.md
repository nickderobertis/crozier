# The renamed request options in the docs

**Kind:** `fern-defect`. Measured at Fern CLI 5.216.0 / fern-python-sdk 5.42.0.

The measurement
[`request-options-body-property`](../../fern-measurements/naming-acceptance/request-options-body-property/)
posts an inline body whose properties are `kwargs`, `request_options` and
`self`. Its `fern-expected/` tree, generated by the certified pair, keeps the
body argument `request_options: str` and renames the SDK's own option in every
signature: `_request_options: typing.Optional[RequestOptions] = None` in
`src/fern/dispatches/client.py` lines 35 and 124 and `raw_client.py` lines 30
and 146, forwarded as `_request_options=_request_options` and sent as
`request_options=_request_options`. crozier writes those files byte for byte.

**Fern's docs name the option the method does not take.** `reference.md` line
65 lists the options as `**request_options:** \`typing.Optional[RequestOptions]\``,
beside line 41's `**request_options:** \`str\``: two entries for one name, the
second documenting an argument no method declares. `README.md` lines 128 and
143 document the retry and timeout options as
`client.dispatches.create_dispatch(..., request_options={…})`, which passes the
options dictionary to the body argument. A one-off run (2026-11-26, Python
3.11, httpx 0.28.1, pydantic 2.14.1) made each README retry call against its
own tree's SDK, with the required body value supplied (the options keyword
passed through `**{…}`, since the source spelling repeats a keyword), through
a local HTTP server recording the body it received:

```text
Fern's SDK:    client.dispatches.create_dispatch(request_options="express", request_options={"max_retries": 1})
TypeError: fern.dispatches.client.DispatchesClient.create_dispatch() got multiple values for keyword argument 'request_options'
body sent: []
crozier's SDK: client.dispatches.create_dispatch(request_options="express", _request_options={"max_retries": 1})
body sent: [{'request_options': 'express'}]
```

Without the body value, Fern's call binds the dictionary to `request_options:
str`, and it is sent as the body property while no retry option applies.

crozier documents the option under the method's own name: `**_request_options:**`
in `reference.md` and `_request_options={` in both README calls, every other
byte of each line unchanged, so the documented options bind to the options
argument and the body carries the caller's value.

The line rule admits only `reference.md`'s `**request_options:**` entry ending
in `` `typing.Optional[RequestOptions]` — Request-specific configuration.`` and
a README line opening `client.` and ending `request_options={`, each beside
crozier's same line with `_request_options`, in a tree some raw method of which
declares both `request_options` and `_request_options`. Its unit test rejects
the body argument's own entry, another file and a tree with no renamed option.
`naming_acceptance::naming_acceptance_documents_generate_as_the_certified_pair_does`
holds the untouched tree to the certified one under the ledger, and
`naming_acceptance::sdk_env_request_options_body_property_sends_beside_the_sdk_options`
drives the sync, async and raw clients under both Pydantic majors: the body
carries `request_options="express"` and `_request_options`' header reaches the
server.

## A path parameter named `request_options`

The same measurement's `GET /labels/{request_options}` shows the pair's other
answer to the name. Its generated methods keep their own options argument and
rename the path parameter instead: `get_label(self, request_options_: str, *,
request_options: typing.Optional[RequestOptions] = None)` in the sync, async
and raw clients alike, and both docstrings pass `request_options_=`. But
`reference.md`'s worked call is:

```python
client.labels.get_label(
    request_options="request_options",
)
```

Run against the certified pair's own tree (Fern CLI 5.216.0 /
fern-python-sdk 5.42.0, python-enums, from the host's certified-tree store),
that call raises before any request is sent:

```text
TypeError: LabelsClient.get_label() missing 1 required positional argument: 'request_options_'
```

crozier writes `request_options_="request_options",` there, the keyword its
method and both docstrings name, and nothing else on the line or in the
signature changes. The rule's second arm admits only a `reference.md` line
whose only change is `request_options=` written `request_options_=` at its
start, a value that is not an options dictionary, in a tree some raw method of
which declares both `request_options_` and `request_options`. Its unit test
rejects another file, an options dictionary, an unchanged line, and a tree
whose methods take `_request_options`.
