# inline-union-hoisting

**Verdict: user-ruling (ruling 6, `inline-union-types`)** (row `inline-union-hoisting` of [`../union-modelling.tsv`](../union-modelling.tsv)).

`openapi.yml` was authored from scratch for this rule. `fern-expected/` is Fern CLI 5.163.1 with `fernapi/fern-python-sdk` 5.41.3's complete, comment-stripped output for it, generated by `tools/fern-goldens/fern-references.py generate measurements` for the `docs/fern-measurements/cases.tsv` cases `handed-off/union-modelling/inline-union-hoisting` and `handed-off/union-modelling/inline-union-hoisting/literals`, under the shared Fern lock. `literals/fern-expected/` is the same document generated with `enum_type` unset (crozier's `literals` mode); it is committed because the enum mode changes more than `core/enum.py` here.

## The rule

A `oneOf` of one `$ref` under no `discriminator` mapping (with no `discriminator`, or one naming only `propertyName`) is that reference wherever it stands: as an array element (`tools`), as a component (`Kit = ChiselTool`), as the target of an annotated `$ref` (`spare: Optional[ChiselTool]`), as a union member's element (`ToolboxRacks = Union[List[ChiselTool], str]`), and its model keeps its own tag field even where another union (`sets`) discriminates it (a mapping still makes the lone member a variant, as loonfs' golden holds); a property that is `anyOf: [allOf: [$ref Map, annotation], null]` over a map component is that map with its values made optional (`typing.Optional[typing.Dict[str, typing.Optional[str]]]`). Neither hoists a named model.

## The comparison

The certified pair types `tools` `typing.List[ChiselTool]`, keeps `kind: ChiselToolKind` on `ChiselTool`, and types `labels` `typing.Optional[typing.Dict[str, typing.Optional[str]]]`. crozier hoisted a one-variant discriminated union `ToolboxToolsItem` (stripping `kind` from `ChiselTool`) and a `ToolboxLabels(LabelMap)` model. Under ruling 6 (`inline-union-types`) crozier writes the certified pair's inline types: it now byte-matches in both enum modes (repaired in `Builder::discriminated_union`, `inferred_discriminant_property`, `inferred_strip_discriminant_property`, `collect_discriminant_strips`, `strips_members`, `Builder::use_site_copy`, `Builder::variant_ref` and `Builder::field_type_ref`, through `lone_unmapped_reference`). The annotation is a `title`, not a `description`, because a described annotation also moves the field's docstring, the separate `nullable-anyof-allof-described-member` rule of the schemas record.

Held by `inline_unions_are_written_as_the_certified_pair_writes_them` in `crates/crozier-e2e/tests/e2e/union_modelling.rs`: crozier generates `openapi.yml` and the SDK must byte-match `fern-expected/` (and `literals/fern-expected/` in `literals` mode where committed) apart from the catalogued departures the ledger records for the tree, and the pre-repair spelling written back into crozier's output must fail that comparison. The unit test `a_lone_reference_element_and_an_annotated_nullable_map_hoist_nothing` in `src/ir.rs`'s `union_modelling_tests` drives the repaired lowering on the same document.
