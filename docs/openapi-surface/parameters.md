# OpenAPI surface coverage — Parameters, headers and examples

Classified entries for the `parameters` region.

This inventory was derived from the normative OpenAPI 3.0.4 and 3.1.1 object
sections, not from crozier's implementation: enumerate every fixed field of the
Parameter, Header, and Example Objects; enumerate the Parameter Object's closed
`in` and `style` vocabularies; take the specification's legal style/location
pairs and cross each with scalar, array, and object schemas; then add the three
reusable Components maps and the parameter placement, Reference, and merge rules.
Repeating those steps yields the rows below. `schema` is inventoried only as the
Parameter/Header field: Schema Object fields and all JSON Schema keywords belong
to [schemas](schemas.md).

The Header Object fields below cover Header Objects reached through both response
headers and Encoding headers. Their containing `Response Object.headers` and
`Encoding Object.headers` fields belong to [bodies and media](bodies-media.md),
so they are cross-linked here rather than duplicated as entries. Reference Object
semantics themselves belong to [document and paths](document-paths.md); this file
owns only reaching a Parameter through one.

Evidence comes from `just surface-census --json`, run over every registered
source. Atomic evidence uses the selector printed in
each cell. Conjunction evidence was produced read-only from the same census
instrument: its `registered_sources` and strict `load_document` functions loaded
the identical source set, then declarations were counted only when `style`, `in`,
and the schema shape occur on the same Parameter node. Counts are declaration
sites, not generated files. A limitations verdict is copied exactly from
`docs/fern-limitations.md`; `golden` wins when both forms of evidence exist.

## Scope

Parameter, Header and Example objects, and `components.parameters`,
`components.headers`, `components.examples`.
