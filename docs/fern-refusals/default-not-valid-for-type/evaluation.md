# default-not-valid-for-type: refuse

Baseline: `2b046a72f1fb687c5ef2399d492a5fd2b57cab3b`. No SDK repair.
Measurements use CPython 3.12.3 and mypy 1.13.0 with the generated
`pyproject.toml` configuration and declared dependencies.

The [probe](evaluation-logs/probe.log) imports its package and client and
reports zero mypy errors. Its integer query `page` declares a string default
`one`. The [public client journey](evaluation-logs/probe.wire.log) omits `page`
when omitted by the caller, sends an explicit integer as `page=2`, and parses
the declared empty 204 as `None`. It never turns the malformed default into
an integer; no wire name is changed.

The representative [Unifi Network v9.2.86 document,
`25c97d8d735203e4d9279e3c7c48ab33730e52555fd7e80a3b777a5a02b6e1bb`](evaluation-logs/population.log)
imports its package and client but reports **eight mypy errors** under its own
configuration: missing generated access types and repeated access definitions.
Its `HotspotVoucherCreationRequest.count` declares an integer with string
default `1`. The [wire journey](evaluation-logs/population.wire.log) sends
`POST /v1/sites/SITE/hotspot/vouchers` with declared `name` and
`timeLimitMinutes` fields, omits unspecified `count`, and sends an explicit
integer count unchanged. The declared vouchers response parses correctly.
This local wire behavior does not rescue a package that fails its own type
check. The class therefore always refuses.

Pinned Fern checks distinguish invalid numeric field/parameter defaults from
accepted metadata: [string integer](evaluation-logs/fern-integer-string-number.log),
[boolean integer](evaluation-logs/fern-integer-boolean.log), [fractional integer](evaluation-logs/fern-integer-fraction.log),
[string number](evaluation-logs/fern-number-string.log), and
[boolean number](evaluation-logs/fern-number-boolean.log) are refused;
[null integer](evaluation-logs/fern-integer-null.log),
[string boolean](evaluation-logs/fern-boolean-string.log),
[numeric string](evaluation-logs/fern-string-number.log), and
[valid number](evaluation-logs/fern-number-valid.log) and
[integral floating-point integer](evaluation-logs/fern-integer-integral-float.log)
are accepted.
Fern ignores defaults on unused [primitive declarations](evaluation-logs/fern-unused-integer.log)
and [response primitive declarations](evaluation-logs/fern-response-integer-valid-yaml.log),
but checks [unused object properties](evaluation-logs/fern-unused-property.log).
The [CLI assertion failed with only this predicate disabled](evaluation-logs/refusal-e2e-induced-red.log),
writing 36 files instead of refusing. The [parameter-reference assertion also
failed with only reference traversal disabled](evaluation-logs/reference-e2e-induced-red.log).
Pinned [shared-parameter](evaluation-logs/fern-shared-parameter.log) and
[referenced-parameter](evaluation-logs/fern-referenced-parameter.log) checks
confirm the same numeric refusal. The CLI journey covers those boundaries and integer-default recovery, including
identical generated bytes in both modes for accepted documents.

[All 15 population documents](evaluation-logs/population-refusals.jsonl) were
retrieved and refused in both modes with exit 1, no files and one stderr line.
Where another registered class is diagnosed first, the log names that class;
strict refusals include `fern-strict` as the cause.
