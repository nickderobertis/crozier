# Schema combination independence documents

Authored from scratch as the three documents of
`combo-annotated-ref-to-nullable-target`'s independence proof in
[`combination-independence.toml`](../../openapi-surface/combination-independence.toml).

| Directory | Document |
|---|---|
| `annotated-ref-nullable-target-first` | `Entry.memo`, a required annotated `$ref` (`allOf: [$ref Memo, {description}]`) to a string that is not nullable. |
| `annotated-ref-nullable-target-second` | `Entry.note`, a required plain `$ref` to the nullable string `Remark`. |
| `annotated-ref-nullable-target-both` | Both properties, and `Entry.remark`, a required annotated `$ref` to `Remark`. |

Each `Entry` also declares an optional `id`, so every document runs the
model's duplicate-field check over more than one property. The both document
holds each single feature beside the conjunction, so the instrumented union
test (`IndependentCombinationTest`) compares the conjunction's regions against
runs that reach the same scaffolding; it executes exactly their union in the
audited handlers.

All three complete trees were freshly generated by the certified pair declared
in [`metadata.json`](../../../assets/scaffolding/metadata.json), through the
measurement rows in [`cases.tsv`](../cases.tsv). Run each named case separately
under the shared Fern lock:

```sh
flock "${XDG_CACHE_HOME:-$HOME/.cache}/crozier/fern-generation.lock" \
  just fern-references measurements \
  schema-independence/annotated-ref-nullable-target-first
```

Repeat for `second` and `both`, and for each `…/expected-literals` case, a
complete literals-mode tree: the literals mode writes no `core/enum.py`, so the
proof holds each document to both modes. They
exposed the annotated-`$ref` description precedence held by
[`union-inheritance/annotated-ref-description-precedence`](../union-inheritance/annotated-ref-description-precedence/).
