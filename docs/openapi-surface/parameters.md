# OpenAPI surface coverage — Parameters, headers and examples

Classified entries for the `parameters` region, against the boundary in
`## Scope` below.

## Scope

Parameter, Header and Example objects, and `components.parameters`,
`components.headers`, `components.examples`.

## How the feature list was enumerated

From the normative OpenAPI 3.0.4 and 3.1.1 object sections, not from crozier's
source. Repeating these five steps in order reproduces the 70 rows below:

1. **Fixed fields.** Take the *Fixed Fields* table of the Parameter Object, the
   Header Object and the Example Object, and emit one row per field. That is 13 +
   11 + 4 = 28 rows. (The Header Object's table is the Parameter Object's minus
   `name` and `in`, which is why it is 11.)
2. **Closed vocabularies.** Emit one row per member of each closed value set a
   field of step 1 draws from: the four `in` values. That is 4 rows.
3. **The serialization matrix.** The specification's *Style Values* table fixes
   which `style` is legal in which `in`, and each cell is then crossed with a
   scalar, an array and an object schema — the three shapes its *Style Examples*
   table distinguishes. `matrix`/`label` are path-only, `simple` is path and
   header, `form` is query and cookie, and `spaceDelimited`/`pipeDelimited`/
   `deepObject` are query-only: 7 legal style/location cells × 3 schema shapes =
   **27 features**, carried by 26 rows. The one merge is `label` with an array and
   `label` with an object, which [`../fern-limitations.md`](../fern-limitations.md)
   rules on under the single key `label-array-or-object`; splitting it would
   invent two keys that join on nothing, so one row carries both and says so.
4. **Modifier crossings the ledger already rules on.** `explode` and `content` are
   fields (step 1), but the ledger also rules on specific crossings of them, and a
   crossing is a feature of its own. Crossing `content` with the four `in` values
   gives 4 rows; the two `explode: true` crossings the ledger names give 2.
5. **Reuse and placement.** The three Components maps this region owns, plus the
   three placement rules the specification states for a parameter: reaching one
   through a Reference Object, declaring one on a Path Item, and an Operation-level
   parameter overriding a Path Item-level one of the same `(name, in)`. That is 6
   rows.

28 + 4 + 26 + 6 + 6 = **70**. Steps 1 and 3–4 stack rather than overlap: "the field
is declared at all" and "the field is declared with *this* value, in *this*
location, over *this* schema shape" are different questions, and a `golden` answer
to the first says nothing about the second — which is the whole point of the
matrix.

Three neighbours are cross-linked rather than enumerated, so no feature lands in
two files. The Header Object rows cover Header Objects reached both ways the
specification allows — a Response Object's `headers` and an Encoding Object's
`headers` — but those two containing *fields* are
[bodies and media](bodies-media.md)'s. Reference Object semantics are
[document and paths](document-paths.md)'s; only the one case of reaching a
*Parameter* through a `$ref` is enumerated here. And `schema` is inventoried
only as the Parameter/Header field it is — every Schema Object field and JSON
Schema keyword is [schemas](schemas.md)'s, wherever it appears.

## Method notes

**What was run.** `just surface-census --json`, exit 0. Every `census <selector>`
cell is that run's `(selector, fixture, count)` rows for the selector, aggregated;
every *"declared by no registered source"* cell is the phrase the instrument
itself prints for an absent selector, reproducible one selector at a time with
`just surface-census --selector header.content`.

**The conjunction pass.** The census emits one row per *field*, so it cannot on
its own answer whether a `style`, an `in` and a schema shape meet on the same
node. A read-only pass supplies that, and it re-uses the census rather than
re-implementing it: import `scripts/openapi-surface-census.py`, call its
`registered_sources()` and `load_document()` so the source set and the loader are
identical, then

- take every node that literally **is** a Parameter Object — an entry of a Path
  Item `parameters` list, an entry of an Operation `parameters` list, or a value
  of `components.parameters`. An entry that is a `$ref` is a *use*, not a
  declaration, and is not counted (counting it would multiply one shared
  parameter by its call sites);
- group those nodes by `(style, in, schema shape)`, where the shape follows the
  parameter's `schema` through local `$ref`s and reads `type` (a 3.1 nullable type
  array reduces to its non-`null` member), falling back to `items` /
  `properties` / `additionalProperties`, then to a single agreed shape across
  `allOf` / `anyOf` / `oneOf`.

The pass is self-checking, and that check is the reason to trust the matrix: its
declarations must total the census's own `parameter.style` count. They do —
**167**, fully partitioned across the seven conjunctions the corpus declares, with
none dropped for a schema behind a `$ref`. The `parameter-reference` and
`operation-overrides-path-item-parameter` rows come from the same pass, counting
`$ref` entries at parameter sites and `(name, in)` collisions between a Path
Item's list and its operations' lists respectively.

**Golden-backing.** The census reads every registered *source*, and not every
registered source is a *golden*: some carry no `tests/fixtures/<name>/expected/`
tree, because Fern cannot generate them or has not yet — the status tables of
[`../../tests/fixtures/CORPUS.md`](../../tests/fixtures/CORPUS.md) own the reason
for each. The index's first category rule asks for a registered **golden**
fixture, so a row here is `golden` only when at least one golden-backed source
declares the feature, while its evidence cell still lists every declaring
registered source. Recompute the split rather than trusting a copy:

```sh
just surface-census --json \
  | python3 -c 'import json,sys,pathlib; print(*sorted(s["fixture"] for s in json.load(sys.stdin)["sources"] if not pathlib.Path("tests/fixtures",s["fixture"],"expected").is_dir()),sep="\n")'
```

Two rows turn on it, and each says so in its own evidence cell: the only source
declaring `parameter-style-matrix-path-scalar` is `appng-rest-api` and the only
one declaring `operation-overrides-path-item-parameter` is `asana.com`, neither
golden-backed, so both are `gap` rather than `golden`. Land a golden for either
and its row is re-measured, not merely re-worded.

**Crozier sites.** Measured against `src/`, not assumed. `Parameter::style` is
read at exactly one place in the whole crate — inside `build_endpoint`'s
query-parameter arm in `src/ir.rs` — so every non-query style crossing scores
`none`. `ParameterLocation::Cookie` is likewise read once, in the same function's
`has_unsupported_params` matcher, and the Operation-over-Path-Item override once,
in `normalize_parameters` in `src/openapi.rs`. No Header Object exists in
crozier's model at all: neither `Response` nor `Encoding` carries a `headers`
field for one to hang off, which is why every Header Object row
classified `gap` scores `none`.

**Not settled here.** This file classifies; it runs no Fern and registers no
fixture. Whether a `FIXTURE` row's witness exists in a redistributable, immutable
form is a screening question for
[`../../tests/fixtures/AGENTS.md`](../../tests/fixtures/AGENTS.md), and a `PROBE`
row's answer belongs in [`../fern-limitations.md`](../fern-limitations.md).


### Witness search (issue #188)

This region has one `PROBE` row, `parameter-style-matrix-path-scalar`, and it
reached that class for a reason no other row of this file rests on: a real-world
document declaring the shape is already **registered here** — `appng-rest-api`,
[`CORPUS.md`](../../tests/fixtures/CORPUS.md) row 70 — and carries no committed
golden, so the census sees the declaration while no byte comparison does. The
issue's question is therefore two questions for this row, and the record below
answers both in order: does the generator still refuse that document at the
version the corpus's own provenance records, and, if it does, does another
document declaring a `matrix` path parameter over a scalar schema exist anywhere.

**The first answer is yes, and it is now measured rather than inherited.**
`CORPUS.md`'s batch-4 ledger recorded only *"generator exits 1 at 5.20.0 despite
`fern check` passing"*. Re-run for this change through
[`../fern-goldens.md`](../fern-goldens.md)'s Route A — the local Docker loop, at
the pin `tests/fixtures/eos.local/expected/.crozier-fern-golden.json` records,
`fernapi/fern-python-sdk` **5.20.0** — generation exits **1** with

```
[api]: python-sdk appNg.yml -> service
                  appNg.yml
                  [error] Service requires auth, but no auth is defined.
[api]: python-sdk Found 1 errors and 0 warnings in 0.114 seconds.
```

and a standalone `fern check` over the same document at Fern CLI **5.114.0** now
exits **1** on that same one error, where the batch-4 CLI passed it. The cause is
not the `matrix` style at all: appNG's only security scheme is `appNGCookie`,
`type: apiKey` with `in: cookie`, and Fern's importer drops cookie API keys — the
behaviour [`../fern-limitations.md`](../fern-limitations.md) records under
`apiKey-cookie` — so the document's single service is left with no auth. It is the
same refusal `tests/fixtures/AGENTS.md` already records for `zerkerlabs-treeship`
and `thenounproject-noun-project-api`, one scheme family along, and this document
now joins them in that list.

**The second answer is that no other real-world document declares it.** The
search below is not a repeat of the corpus's own screening: it reads two complete
document corpora rather than sampling them (APIs.guru's 4,138 and
`jentic/jentic-public-apis`' 74,108, both cloned and grepped), plus a literal
code-search index, GitHub's token-based one, SwaggerHub, Postman and the vendor
portals JAX-RS implies. Every `style: matrix` declaration it found outside appNG
is a tooling test stub, an example fixture or a document that declares the style
somewhere other than a path parameter — the two closest of those are in the
candidate ledger, because each looks like a witness until it is fetched.

`outcome` is one of four words, spelled as the other regions' subsections spell
them. `witness-found` — a named real-world document declares the feature, at a
credential-free HTTPS URL ending `.json`, `.yaml` or `.yml`, pinned to an
immutable ref, under a redistribution-compatible license, accepted by Fern, and
under a name that is neither registered in
[`CORPUS.md`](../../tests/fixtures/CORPUS.md) nor listed DROPPED or REJECTED
there or in [`tests/fixtures/AGENTS.md`](../../tests/fixtures/AGENTS.md).
`fern-rejected` — such a document was found and Fern refuses it at the pinned ref.
`witness-blocked` — such a document was found but the corpus may not redistribute
it, or it is reachable at no immutable ref. `none-found` — no document reaching
that bar was found at all.
