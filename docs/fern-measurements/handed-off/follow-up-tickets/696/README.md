# Mixed nested null-only type identity

Issue [#696](https://github.com/nickderobertis/crozier/issues/696).
`openapi.yml` was authored from scratch: `Reading.silence` names a component
whose `oneOf` holds a null-only `anyOf` and a two-null `oneOf`.

`fern-expected/` is the complete, untouched comment-stripped tree freshly
generated by Fern CLI 5.163.1 with `fernapi/fern-python-sdk` 5.41.3, through
`tools/fern-goldens/fern-references.py::run_fern` and `strip_into`, using the
workspace of `generate-fern-fixture.sh`, under the shared generation lock.
`fern.log` and `exit-code` record the successful run. There are no enums.

Fern exports `SilenceOne = typing.Optional[typing.Any]` and gives the property
`typing.Optional[SilenceOne]`; no `Silence` alias survives. The base folds
every null composition into `Silence`, changing the public type and module.
`openapi::normalize_null_only_compositions` now preserves the named nested
identity for this exact bare mixed shape and retargets component references
through the existing component-renaming pass. Ordinary null-only unions and
a same-kind nested `anyOf` still fold as before. An existing component owning
the proposed nested name is never overwritten.

Verdict: **parity-gap-repaired**. `crozier compare` byte-matches the complete
tree with the catalogued SDK identity headers applied. The unit test
`mixed_null_compositions_keep_the_nested_type_identity` and real CLI comparison
`follow_up_ticket_matching_outputs_hold_against_the_certified_pair` hold it.
