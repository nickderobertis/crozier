# union-modelling: event-stream-beside-json

A sub-case of the [`union-modelling`](../README.md) cause; **verdict: parity-gap-repaired**.

`openapi.yml` was authored from scratch for this rule. `fern-expected/` is Fern CLI 5.163.1 with `fernapi/fern-python-sdk` 5.41.3's complete, comment-stripped output for it, generated by `tools/fern-goldens/fern-references.py generate measurements` for the `docs/fern-measurements/cases.tsv` cases `handed-off/union-modelling/union-modelling/event-stream-beside-json` and `…/event-stream-beside-json/literals`, under the shared Fern lock. `literals/fern-expected/` is the same document generated with `enum_type` unset (crozier's `literals` mode), committed because the enum mode changes more than `core/enum.py` here.

## The rule

A `text/event-stream` union beside a JSON body on the same response is never read: the operation answers the JSON body, and the event models keep their tag fields.

## The comparison

The certified pair keeps `type: FiringStartedEventType` (and `FiringCooledEventType`) on both event models; crozier stripped the tag because it read the stream's `oneOf` as a discriminated union (OpenResponses' 24 streaming events, about 50 files). Repaired in `document_discriminant_strips`. crozier now byte-matches `fern-expected/` in both enum modes.

Held by `union_modelling_document_sub_rules_match_the_certified_pair` in `crates/crozier-e2e/tests/e2e/union_modelling.rs`, which byte-compares crozier's SDK for this document with the committed tree (apart from the catalogued departures the ledger records) and requires the pre-repair spelling to fail that comparison, and by the unit test `an_event_stream_union_beside_json_strips_no_tag` in `src/ir.rs`'s `union_modelling_tests`.
