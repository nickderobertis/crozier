# union-modelling: nullable-reference-member

A sub-case of the [`union-modelling`](../README.md) cause; **verdict: parity-gap-repaired**.

`openapi.yml` was authored from scratch for this rule. `fern-expected/` is Fern CLI 5.163.1 with `fernapi/fern-python-sdk` 5.41.3's complete, comment-stripped output for it, generated by `tools/fern-goldens/fern-references.py generate measurements` for the `docs/fern-measurements/cases.tsv` case `handed-off/union-modelling/union-modelling/nullable-reference-member`, under the shared Fern lock. The enum mode changes nothing here but `core/enum.py` and `.fern/metadata.json`, so no `literals/` tree is committed.

## The rule

A union member naming a component that admits `null` through a `type: null` member is that component made `Optional` in its slot, in a query parameter's hoisted union and in a property's.

## The comparison

The certified pair declares `ListRecordingsRequestSince = typing.Union[typing.Optional[Moment], str]` and `RecordingStartedAt = typing.Union[typing.Optional[Moment], int]`; crozier dropped the `Optional` (gecko's and numbat's `…EventListRequestAfter`). Repaired in `InlineHoister::hoist_param_composition`, `InlineHoister::hoist_union_variant` and `Builder::field_type_ref`. crozier now byte-matches `fern-expected/`.

Held by `union_modelling_sub_rules_match_the_certified_pair` in `crates/crozier-e2e/tests/e2e/union_modelling.rs`, which byte-compares crozier's SDK for this document with `fern-expected/` (apart from the catalogued departures the ledger records) and requires the pre-repair spelling to fail that comparison, and by the unit test `a_member_naming_a_null_admitting_target_is_optional_in_its_slot` in `src/ir.rs`'s `union_modelling_tests`.
