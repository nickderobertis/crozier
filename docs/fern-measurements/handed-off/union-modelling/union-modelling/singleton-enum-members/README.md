# union-modelling: singleton-enum-members

A sub-case of the [`union-modelling`](../README.md) cause; **verdict: parity-gap-repaired**.

`openapi.yml` was authored from scratch for this rule. `fern-expected/` is Fern CLI 5.163.1 with `fernapi/fern-python-sdk` 5.41.3's complete, comment-stripped output for it, generated by `tools/fern-goldens/fern-references.py generate measurements` for the `docs/fern-measurements/cases.tsv` cases `handed-off/union-modelling/union-modelling/singleton-enum-members` and `…/singleton-enum-members/literals`, under the shared Fern lock. `literals/fern-expected/` is the same document generated with `enum_type` unset (crozier's `literals` mode), committed because the enum mode changes more than `core/enum.py` here.

## The rule

A query parameter `oneOf` whose every member is a typed one-value string `enum` is one enum of their values, deduplicated in document order and declared where a lone enum would be; a bare `const` member stays a member of its own. Members that convert to one type once their own `nullable` is set aside collapse to it.

## The comparison

The certified pair declares `OrderPrintRequestFinish` (`NONE`, `MATTE`, `GLOSS`) and types `dpi` `typing.Optional[float]`; crozier declared `…FinishZero` to `…FinishThree` under a union and `OrderPrintRequestDpi = Union[float, Optional[float]]` (Deepgram's `SpeakV1Container`, `SpeakV1Encoding` and `SpeakV1BitRate`). Repaired by `merged_singleton_enum_values` in `InlineHoister::hoist_param_composition` and `parameter_union_is_global`. crozier now byte-matches `fern-expected/` in both enum modes.

Held by `union_modelling_document_sub_rules_match_the_certified_pair` in `crates/crozier-e2e/tests/e2e/union_modelling.rs`, which byte-compares crozier's SDK for this document with the committed tree (apart from the catalogued departures the ledger records) and requires the pre-repair spelling to fail that comparison, and by the unit test `one_value_enum_members_merge_and_nullable_alike_members_collapse` in `src/ir.rs`'s `union_modelling_tests`.
