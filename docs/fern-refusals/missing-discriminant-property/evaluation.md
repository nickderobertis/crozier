Baseline: `2b046a72f1fb687c5ef2399d492a5fd2b57cab3b`. No SDK repair was
made to qualify this class. Checks use CPython 3.12.3, mypy 1.13.0 and the
generated `pyproject.toml`'s own configuration with its dependencies installed.

The [probe output](evaluation-logs/probe.log) imports its package and client
but has **2 mypy errors**, both at the offending element: `raw_client.py` passes
`Pet = typing.Union[Cat, Dog]` to `parse_obj_as` (`arg-type`). The probe's `Pet`

[wire journey](evaluation-logs/probe.wire.log) sends `GET /pets` correctly, but
parses every response as `Cat`, including one naming `kind: dog` and one with
no discriminant. The document's variant selection is lost.

Population representatives, one per publisher, are in

v9.4.19 (`1c0e05f4…`) imports, but has **8 mypy errors** (`no-redef` of

## What Fern refuses

Fern validates each endpoint's example against its discriminated unions, and
reports `Missing discriminant property ("<name>")` at `examples[0] -> request`
or `-> response` when the example value lacks the discriminant. A
**discriminated union** here is a schema with `discriminator.propertyName` and
a non-empty `discriminator.mapping`, and no `anyOf`. With an `anyOf`, Fern
imports an undiscriminated union and [accepts](evaluation-logs/fern-anyof-absent-mapping.log)
the probe shape. An [empty mapping](evaluation-logs/fern-empty-mapping.log)
is accepted. An [unmapped union with an `x-fern-examples` value lacking
`kind`](evaluation-logs/fern-x-fern-example-without-kind-unmapped.log) gets a
different class (`Example is missing required property`). The `fern
write-definition` output, kept in the agent scratch rather than here, shows the
mechanism. Fern's union variants come from the mapping, not from `oneOf`. A
mapping target that does not resolve becomes an `unknown` variant. Fern's own
example of a union picks a variant with a resolved type, and when every variant
is `unknown` the example is `{}`.

Two triggers reach that validation, and crozier detects both:

1. **No `x-fern-examples` on the operation, and every mapping target is a
   missing local pointer.** Fern's autogenerated example is then `{}`. This
   holds in the [response](../../openapi-surface/fern-refusals/probe-logs/missing-discriminant-property.check.log),
   [required](evaluation-logs/fern-request-absent-mapping.log) request body,
   [optional](evaluation-logs/fern-optional-request-absent-mapping.log)
   request body, and an [error response](evaluation-logs/fern-error-response-absent-mapping.log).
   It holds through required properties at any depth measured
   ([12 levels](evaluation-logs/fern-required-depth12-absent-mapping.log)), and
   through optional properties within three object levels
   ([level 3](evaluation-logs/fern-optional-depth3-absent-mapping.log)).
   It holds through [array items](evaluation-logs/fern-array-item-absent-mapping.log),
   [map values](evaluation-logs/fern-map-value-absent-mapping.log),
   [`allOf`](evaluation-logs/fern-allof-absent-mapping.log), and a
   [`nullable`](evaluation-logs/fern-nullable-absent-mapping.log) union. It
   also holds through an undiscriminated union's
   [first member](evaluation-logs/fern-nested-union-absent-mapping.log), and a
   [discriminator with no `oneOf`](evaluation-logs/fern-no-members-absent-mapping.log).
   Fern discards plain OpenAPI `example`s here, so [one naming
   `kind`](evaluation-logs/fern-example-with-kind-absent-mapping.log) does not
   rescue the document. Fern ignores [`x-crozier-examples`](evaluation-logs/fern-x-crozier-example-with-kind-absent-mapping.log),
   and per ruling 1 the detector never reads it.
2. **An `x-fern-examples` value lacks the discriminant** at a `oneOf` union
   with a mapping, even one whose targets all resolve. This covers a
   [response body](evaluation-logs/fern-x-fern-example-without-kind-mapped.log),
   a [request](evaluation-logs/fern-x-fern-request-example-without-kind-mapped.log),
   and a [nested property](evaluation-logs/fern-x-fern-example-nested-without-kind-mapped.log).
   The detector walks only `$ref`s and object properties for this trigger.

Accepted near-misses, each committed as `*-control.yml` with its Fern check
and generate log, generate identical bytes in both crozier modes:
- one mapping target resolving, as the
  [first](evaluation-logs/fern-half-absent-mapping.log) or
  [second](evaluation-logs/fern-first-absent-mapping.log) entry. Fern's example
  takes the resolved variant.
- [`anyOf`](evaluation-logs/fern-anyof-absent-mapping.log) and an
  [empty mapping](evaluation-logs/fern-empty-mapping.log).
- a mapping target that resolves to an [empty schema](evaluation-logs/fern-empty-schema-mapping.log).
- the union [unused by any operation](evaluation-logs/fern-unused-absent-mapping.log),
  or used only by an [`x-fern-ignore`d one](evaluation-logs/fern-x-fern-ignore-operation-absent-mapping.log).
- an optional property at the [fourth object level](evaluation-logs/fern-optional-depth4-absent-mapping.log),
  [even below required levels](evaluation-logs/fern-required3-optional-absent-mapping.log).
- the union as an undiscriminated union's [second member](evaluation-logs/fern-nested-union-second-absent-mapping.log).
- an [`x-fern-examples` value naming `kind`](evaluation-logs/fern-x-fern-example-with-kind-absent-mapping.log),
  which replaces Fern's own example.
- a [plain `example` lacking `kind`](evaluation-logs/fern-example-without-kind-mapped.log)
  on a resolvable union.

The detector stays inside the measured boundary wherever Fern's reach is
unmeasured, because over-refusal is worse than a missed refusal. It reads only
`application/json` bodies, the first 2xx response and 4xx/5xx responses, and
does not walk `x-fern-examples` through arrays or unions.

**Not detected.** UniFi's documents reach the diagnostic a third way. A
discriminated `Client details` declares `access: {}`, which Fern makes an
`unknown` base property. Each variant redeclares `access` as another
discriminated union, and Fern's example fills it from the base property
(`access: {key: value}`). That interaction depends on Fern's base-property and
variant merge, so it is left to the classes that already refuse these
documents.

## Verification

The [probe assertion failed with only the autogenerated-example predicate
disabled](evaluation-logs/refusal-e2e-induced-red.log), writing 40 files. The
[`x-fern-examples` assertion failed with only its predicate
disabled](evaluation-logs/x-fern-examples-e2e-induced-red.log). Both passed
again once restored. The CLI journey
`missing_discriminant_refusal_follows_fern_examples_and_recovers_with_a_mapped_variant`
refuses the probe and the 16 `*-probe.yml` shapes in both modes. Pointing
`cat` at the existing `Cat` recovers generation, with identical bytes in both
modes, as does every control.

[All 13 population documents](evaluation-logs/population-refusals.jsonl),
measured with the finished detector, were retrieved at their digests and
refused in both modes: exit 1, no files, one class/element stderr line and the
strict cause when applicable. Classes that fire first refuse each of them:
`default-not-valid-for-type` for UniFi, `list-default-not-array` for
Cloudflare, `default-not-enum-value` for Jira. The corpus byte-match passes
with `fern-strict` off and on (189/189 each).
