# Binary bodies in worked calls

**Kind:** `fern-defect`. Measured at Fern CLI 5.216.0 / fern-python-sdk 5.42.0.

A binary string body under a media type other than `application/octet-stream`
is the method's single `request: bytes` argument. The measurement
[`binary-body-examples`](../../fern-measurements/worked-examples/binary-body-examples/)
declares three under `*/*`: `upload_blob` with no example, `attach_note` with
the example `note "quoted" body` and `attach_receipt` with `café receipt`. Its
`fern-expected/` tree, generated by the certified pair, declares
`request: bytes` for each (`src/fern/blobs/client.py` lines 54, 81 and 112) and
passes each value as a str: `request="string"` (`README.md` lines 43 and 74,
`reference.md` line 80, `client.py` lines 74 and 208),
`request='note "quoted" body'` (`client.py` lines 105 and 247) and
`request="note \"quoted\" body"` (`reference.md` line 139), and
`request="café receipt"` (`client.py` lines 136 and 286, `reference.md` line
206). apideck's file-storage API (corpus `apideck.com-file-storage`) is the
real witness: `files.upload` passes `request="string"` and
`upload_sessions.upload` its declared `request="<binary string>"`, both to
`request: bytes`, in its docstrings and `reference.md`.

**Fern's calls do not type-check.** `worked_examples_typecheck.py` extracts
every worked example of the tree (each docstring `Examples` section,
`reference.md` usage and README call, its own module) and runs pyright 1.1.414
in basic mode against the tree's own `src/`:

```text
$ python crates/crozier-e2e/tests/e2e/worked_examples_typecheck.py \
    docs/fern-measurements/worked-examples/binary-body-examples/fern-expected
docstring_2.py:6:13 - error: Argument of type "Literal['café receipt']" cannot be assigned to parameter "request" of type "bytes" in function "attach_receipt"
docstring_4.py:11:17 - error: Argument of type "Literal['note "quoted" body']" cannot be assigned to parameter "request" of type "bytes" in function "attach_note"
readme_10.py:6:13 - error: Argument of type "Literal['string']" cannot be assigned to parameter "request" of type "bytes" in function "upload_blob"
... the same for every other docstring, reference.md and README call
11 errors, 0 warnings, 0 informations
```

crozier passes the same text as bytes: the str literal behind a `b` prefix
where it is ASCII (`request=b"string"`, `request=b'note "quoted" body'`), and
its UTF-8 octets as `\xNN` escapes where it is not
(`request=b"caf\xc3\xa9 receipt"`, written `b"caf\\xc3\\xa9 receipt"` inside
a docstring, which renders it as the former, as every docstring escape is
doubled under `docstring-example-escapes`). The same check over crozier's tree
reports `11 worked examples type-check`. The annotation, the request
construction and every other byte match the certified tree.

The line rule admits only a `request=` argument whose Fern value is a str
literal and whose crozier value, at the same indent, is a bytes literal holding
exactly that text's UTF-8 encoding (read after undoing a docstring's doubled
backslashes in a `client.py`), in `README.md`, `reference.md` or a `client.py`
of a tree some raw method of which annotates `request` `bytes`. Fern's
`"string"` beside a JSON binary method stays `binary-json-body-example`'s. Its
unit test rejects other text, a str on crozier's side, another file, a shifted
indent and a tree with no bytes `request`.
`worked_examples::binary_body_examples_are_bytes_in_every_writer` holds the
untouched tree to the certified one under the ledger, which pins every
occurrence, and `worked_examples::sdk_env_worked_examples_bind_and_their_repaired_values_validate`
type-checks crozier's calls in both enum modes, fails Fern's, and validates the
values against their binary string schemas with
[`validate.py`](invalid-example-values/validate.py).
