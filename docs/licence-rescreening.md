# Screening the licence-blocked candidates against the widened rule

The corpus's admissible-licence rule widened
([`corpus-licensing.md`](corpus-licensing.md)), and every screening outcome
recorded under [`openapi-surface/`](openapi-surface/) was measured against the
narrower one. This file is the rescreening: **one line per candidate the six
region files record as blocked on a licence, or as never screened because a
licence stopped it first**, saying what the widened rule says about that
document, what Fern does with it, and which coverage rows it would settle.

**This file reports; it does not register.** Adding a
[`CORPUS.md`](../tests/fixtures/CORPUS.md) row, saving a golden and reaching
parity is separate work, governed by
[`../tests/fixtures/AGENTS.md`](../tests/fixtures/AGENTS.md). What is settled
here is only which candidates are worth that work.

`just lint-licence-rescreening` holds the table below to the shape the
registering node reads it with, and `just test-licence-rescreening` proves that
gate still discriminates; both are in `just check`.

## Where the candidates came from

The six region files' `### Witness search (issue #188)` tables and the candidate
ledgers beneath them. That search read both complete document corpora whole — all
4,138 APIs.guru documents at `f04b8d0bcd39c52e1cf3ad7a5fe744709832ae49` and all
74,240 `jentic/jentic-public-apis` documents at
`eb9d12a2684b0fbcb5aecf51e8ae54dba0929743`, beside five further sources — and is
the authoritative one, so **no fresh world search was run here**. Every candidate
below is one those tables already name; the input to this file is their record and
nothing else.

A candidate is in scope when the region file's own text names a licence among
what blocks it, whether as the sole obstacle or beside a Fern refusal, or when it
says the candidate went unscreened because the licence settled it first. A
candidate a region file blocks on something else — a synthetic fixture, a
third-party transcription, a shape it turns out not to declare — is not rescreened
here, because the widening does not touch what stopped it.

## The screening path

The same two-stage screen the region files' own searches ran, because this
repository's rejected ledger is full of documents that pass the first stage and
are refused by the second, and a whole class of failure exits zero having
generated an empty SDK. For each candidate the widened rule admits:

```bash
curl -sSL -o openapi.<ext> "<the pinned URL in the ref column>"
# scaffolded into a workspace: fern.config.json {"organization":"fern","version":"5.114.1"},
# generators.yml with api.path: openapi/openapi.<ext> and one generator,
#   fernapi/fern-python-sdk 5.20.0, pydantic_config.enum_type: python_enums
fern check
fern generate --group python-sdk --preview
```

That is the workspace [`../scripts/generate-fern-fixture.sh`](../scripts/generate-fern-fixture.sh)
builds, at the Fern CLI and generator versions the region files' searches record —
CLI **5.114.1**, `fernapi/fern-python-sdk` **5.20.0**, the version
`tests/fixtures/eos.local/expected/.crozier-fern-golden.json` pins. Every exit
status and diagnostic in the table below is that run's own output on this host,
quoted rather than paraphrased. Declaration counts are re-measured out of the
fetched bytes with `scripts/openapi-surface-census.py`'s own object model, not
inherited.

A candidate the widened rule does **not** admit was not put through Fern, and its
line says `not run` with the reason. The widening admits grants; a document that
grants nothing has no condition to satisfy, so its Fern verdict could not change
its outcome. `just lint-licence-rescreening` requires that reason to be written
out rather than left blank.

## How to read a line

* **admission** is exactly `admitted` or `still-blocked` — whether
  [the rule](corpus-licensing.md) as it now stands reaches the document.
  `admitted` says the licence is no longer what stops it; it does not say the
  document is registrable, which the Fern columns and the corpus's own
  real-world and immutability rules decide.
* **pinned ref** is the reference the screening was taken at: a commit, an
  APIs.guru version reference, or `none —` and why the world offers no immutable
  one.
* **rows it declares** are the coverage rows of the six region files the document
  would bear on, with the count re-measured in its fetched bytes. Only a
  coverage-row key may be written in backticks in that column, because the gate
  reads every backticked token there as a row name and fails on one no region
  file carries; write a field or keyword name plainly instead.

## What the record settles

**Six candidates the widening admits are accepted by Fern at both stages**, and
five of the six declare a coverage row. In the order a registering node should
weigh them:

1. `aces/Loris` — settles `parameter-style-spacedelimited-query-scalar`, whose
   census count across every registered source is **0**, and is the second-best
   candidate for `parameter-style-pipedelimited-query-scalar` behind that row's
   own Fern-rejected witness. Two rows from one 12,810-byte document.
2. `drakkan/sftpgo` — the richest `media-type-range` declarer found anywhere,
   ten sites over five distinct ranges.
3. `eclipse-ditto/ditto` — settles `format-iri-reference`, and is the only
   admitted candidate for it Fern accepts. **Its Fern verdict changed**: the
   schemas ledger records `fern check` exiting 1 on `thingId`, and this rerun at
   CLI 5.114.1 exits 0. A registering node should take that from here rather
   than from the ledger.
4. `APIs-guru/openapi-directory` `googleapis.com/servicebroker` — settles
   `duplicate-normalized-paths` with four collision sites.
5. `advplyr/audiobookshelf` — a second `media-type-range` declarer, three sites
   all `image/*`; worth registering only if `sftpgo` is rejected downstream.
6. `Alia5/steaminputdb.com` — accepted by Fern and admitted by the rule, but it
   declares no row, so it settles nothing.

**Seven candidates the widening admits are refused by something else.** Fern
refuses `nextcloud/server`, `openfoodfacts/food-logging`, `dns-technologies/SDMS`,
`dunglas/mercure`, `jentic`'s openEHR redistribution and
`hpi-schul-cloud/schulcloud-server`; `openbankingproject.ch` passes the check and
is refused by the generate. Of these, `openbankingproject.ch` is the one to
retry after a Fern upgrade — it is the largest
`security-optional-requirement-operation` declarer in APIs.guru and fails on a
single generator error.

**Three of the admitted candidates turn out to declare no row at all** —
`Alia5/steaminputdb.com`, `hpi-schul-cloud/schulcloud-server` and
`nextcloud/server` — and the last of those is a correction to a region file
rather than a screening outcome: its two `$comment` occurrences are a schema
property *named* `$comment` (once in `properties`, once in the sibling
`required` list), not the keyword, so `schema.$comment` is 0 there and the
`dollar-comment` supply is `openfoodfacts/food-logging` alone. The first two
were already recorded as declaring nothing, on grounds the widening does not
touch; this rescreening confirms both against the object model.

**Every remaining candidate stays blocked, and the reason is the same one in
every case**: the licence grants nothing. An absent licence, a proprietary one,
and one the GitHub API reports as `NOASSERTION` all leave the default of all
rights reserved, so there is no condition provenance could satisfy. The
Business Source License on `golemcloud/golem` is the one line that is not that
shape: it grants redistribution and restricts use of what it redistributes,
which is the third of [`corpus-licensing.md`](corpus-licensing.md)'s
categories rather than the second. Six rows stay `witness-blocked` on a
no-grant document that is the only declarer their region's search reached:
`dollar-anchor` on `inkeep/chat-api-openapi-schema`, `format-idn-email` on
`wttw/aboutmyemail`, `format-relative-json-pointer` on `geo-engine/BioIS`, and
`http-hoba`, `http-scram-sha-1` and `http-scram-sha-256` on the one SwaggerHub
`Auth Test` document. No widening of a licence rule can move those.
