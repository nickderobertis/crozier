# Operation combination controls

These documents were authored from scratch to measure media selection. They
do **not** prove independent handling of `combo-error-multiple-media`: its
`operation.context:error-multiple-media` selector entails `operation.responses`,
so a document with the former alone cannot exist. The manager's entailment
amendment leaves that combination open unless its own interaction region and
a registered real witness prove it.

| Directory | Document |
|---|---|
| `error-multiple-media-first` | A single-media error beside a JSON success. |
| `error-multiple-media-second` | A multiple-media success, with no error response. |
| `error-multiple-media-both` | A multiple-media error beside a JSON success. |

All three complete trees were freshly generated by the certified pair declared
in [`metadata.json`](../../../assets/scaffolding/metadata.json), through the
measurement rows in [`cases.tsv`](../cases.tsv). Run each named case separately
under the shared Fern lock:

```sh
flock "${XDG_CACHE_HOME:-$HOME/.cache}/crozier/fern-generation.lock" \
  just fern-references measurements \
  operation-independence/error-multiple-media-first --version 5.41.3
```

Repeat for `second` and `both`. Each `comparison.json` records a successful
`crozier compare` against that case's freshly generated `fern-expected/`, with
all catalogued departures applied. The reference command copies that complete
tree into `CROZIER_REFERENCE_OUTPUT`; it does not regenerate Fern during the
comparison. Repository and dispatch scratch prefixes in the reports are
replaced by `<repo>` and `<scratch>`.

An exploratory region-union measurement found 156 regions for `first`, 59 for
`second`, and 156 for `both`, within the four audited error handlers, with the
combined set equal to the union. These semantic controls are not the impossible
selector-alone control and earn no independent proof class.
